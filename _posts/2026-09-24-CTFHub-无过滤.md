# 笔记

## 失败原因：

1. 为什么 127.0.0.1; cat 84281830621188.php 会空白？

即使文件名对，直接 cat 一个 PHP 文件也经常看不到内容。

因为 PHP 文件内部包含类似 <?php 这样的标签，当命令结果被 print_r 输出到 HTML 页面时，浏览器会把它当作 HTML 标签解析（隐藏掉），或者文件内容包含 \0 等特殊字符（二进制）导致 CMD 和页面卡断。这就是你看起来“又变回了一开始的页面状态”的原因。

2. 为什么 find、ls、cat /flag 这些也失败？
  
find / -name "*flag*" -exec cat {} \; 太长，在 URL 编码传参过程中很容易被截断，或者被 exec 函数的限制给吃掉（你截图中出现的 0x11000040 就是报错乱码）。

这个靶场比较干净，flag 没有直接写在 /flag 或者 /tmp 下，你推测的路径都不对。

cat /var/www/html/index.php 成功了，其实这个命令很重要，它证明了网站源码目录就是 /var/www/html/，同时也暗示了 flag 就是藏在同目录下那个随机命名的文件里。

## 这道题主要学习了：

1. 编码绕过： base64 会把文件的内容（不论里面有 PHP 标签、还是二进制乱码）统统转换成一串纯正的英文字母和数字（即 ASCII 字符）。这样，当它通过 exec 执行完、再通过 print_r($res) 输出到网页时，就不会因为特殊字符丢失或者被浏览器解析破坏。
