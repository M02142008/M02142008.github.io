# 从 Fatal error 到 login success：Pikachu「基于表单的暴力破解」复盘
> 本来以为这题就是"抓个包、挂个字典、跑出弱口令"，十分钟的事。结果真正卡住我的不是爆破，而是一个数据库没初始化导致的 `Fatal error`。更尴尬的是，我最后是**直接输入密码**通关的——这不算爆破。这篇把常规解法、我的实际操作、踩过的坑和真正学到的东西都记一遍。
## 一、环境与目标
| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 运行环境 | phpStudy（Apache 2.4.39 + MySQL 5.7.26 + PHP 7.3.4 NTS） |
| 站点根目录 | `D:\Pikachu` |
| 访问方式 | `http://pikachu/`（hosts 中 `127.0.0.1` 已指向 `pikachu`） |
| 关卡位置 | 暴力破解 → 基于表单的暴力破解 |
| 页面地址 | `http://pikachu/vul/burteforce/bf_form.php` |
| 主要工具 | Burp Suite |
目标很简单：从一个登录框里拿到可用账号，页面回显 `login success`。
## 二、这道题在考什么
### 2.1 页面长什么样
最朴素的登录框：Username、Password、Login。没有验证码，没有找回密码，也没有任何额外的校验环节。
### 2.2 看源码
`vul/burteforce/bf_form.php` 的核心逻辑不长，直接摘出来：
```php
if(isset($_POST['submit']) && $_POST['username'] && $_POST['password']){
    $username = $_POST['username'];
    $password = $_POST['password'];
    $sql = "select * from users where username=? and password=md5(?)";
    $line_pre = $link->prepare($sql);
    $line_pre->bind_param('ss', $username, $password);
    if($line_pre->execute()){
        $line_pre->store_result();
        if($line_pre->num_rows > 0){
            $html .= '<p> login success</p>';
        } else {
            $html .= '<p> username or password is not exists～</p>';
        }
    }
}
```
有三个细节值得注意：
1. SQL 用的是**预编译**（`?` 占位 + `bind_param`），所以这里**打不了 SQL 注入**，别把方向搞错；
2. 密码在库里存的是 `md5()`，登录时也是先 `md5()` 再比对；
3. 成功和失败是**两句不同的回显文本**——这正是后面判断爆破结果的依据。
### 2.3 缺失的三个控制
| 控制措施 | 有没有 |
| --- | --- |
| 验证码 | 没有 |
| 失败次数锁定 | 没有 |
| 请求频率限制 | 没有 |
三个全没有，意味着可以无限次、零成本地重复提交。剩下要做的只有一件事：**把密码一个个试过去**。
## 三、常规解法：Burp Intruder 爆破
这是这道题的标准姿势。虽然我自己的实际过程走了弯路（见第四节），但流程本身要记清楚。
### 3.1 抓包
1. Burp 里 `Proxy → Intercept`，确认 **Intercept is on**；
2. 用 Burp 自带浏览器打开目标页面（比手动配系统代理 + 装 CA 证书省事很多）；
3. 用户名填 `admin`，密码随便填个 `123`，点 Login；
4. Burp 拦到的请求大致是这样：
```http
POST /vul/burteforce/bf_form.php HTTP/1.1
Host: pikachu
Content-Type: application/x-www-form-urlencoded
username=admin&password=123&submit=Login
```
5. 右键 → **Send to Intruder**。
抓包的目的不是为了"看"，而是拿到**模板**：请求发到哪个路径、用什么方法、参数叫什么名字。有了模板，才能只替换其中一个字段批量重放。
### 3.2 设爆破点
切到 `Intruder → Positions`：
1. 点 **Clear §**，把 Burp 自动加上的位置全部清掉；
2. 鼠标选中 `password=` 后面的值 `123`，点 **Add §**。
最终只留一个变量：
```
username=admin&password=§123§&submit=Login
```
`Attack type` 保持 `Sniper` 即可。
### 3.3 挂字典
切到 `Intruder → Payloads`：
- `Payload type` 选 **Simple list**；
- 点 **Load** 加载密码字典（Kali 的 `rockyou.txt`，或自建一个几十行的弱口令表）；
- 不想存文件也可以直接 **Paste** 粘贴进去。
### 3.4 加成功标记（关键技巧）
几百条结果靠肉眼一条条翻不现实。用 `Settings → Grep - Match` 加一个特征串：
```
login success
```
结果表里会多一列，命中的那一条会打勾，一眼就能看出来。
### 3.5 开始攻击
点 **Start attack**，等跑完。
然后按 **Length** 排序，或者直接看 `login success` 那一列。响应长度明显不同的、或者 Grep 打勾的那一条，payload 就是正确密码。
> 提醒：Burp **社区版**的 Intruder 是被人为限速的，跑几百个密码要等一阵，不是卡死。
### 3.6 验证
回到页面，用跑出来的账号登录，看到 `login success` 就结束了。
## 四、我的实际操作
流程听起来很顺，但我走的完全是另一条路。
### 4.1 第一步就撞上 Fatal error
第一次提交登录，页面既没成功也没失败，直接崩了：
```
Fatal error: Uncaught Error: Call to a member function bind_param() on bool
in D:\Pikachu\vul\burteforce\bf_form.php:33
```
注意行号 `33`，正好是这一行：
```php
$line_pre->bind_param('ss', $username, $password);
```
`bind_param()` 是 `mysqli_stmt` 对象的方法。报 `on bool` 说明它前面的 `$line_pre` 根本不是对象，而是 `false`——也就是说，上一句 `$link->prepare($sql)` 失败了。
### 4.2 往回推一层
SQL 本身语法没问题，那 `prepare()` 失败还能为什么？基本只剩一种可能：**表不存在**。
去翻 `install.php`，建库脚本里写得很清楚：
```sql
CREATE TABLE IF NOT EXISTS `users` (
  `id`       int(10) unsigned NOT NULL AUTO_INCREMENT,
  `username` varchar(30)  NOT NULL,
  `password` varchar(66)  NOT NULL,
  `level`    int(11)      NOT NULL,
  PRIMARY KEY (`id`)
) ENGINE=MyISAM DEFAULT CHARSET=utf8 AUTO_INCREMENT=4;
insert into `users` (`id`,`username`,`password`,`level`) values
(1, 'admin',   md5('123456'), 1),
(2, 'pikachu', md5('000000'), 2),
(3, 'test',    md5('abc123'), 3);
```
所以真相是：我只把网站跑起来了，**但没做数据库初始化**。`pikachu` 这个库在，`users` 表却不存在。
### 4.3 修复
浏览器打开：
```
http://pikachu/install.php
```
点 **「安装/初始化」**，页面依次出现：
```
数据库连接成功!
新建数据库:pikachu成功!
创建数据库数据成功!
好了，可以开搞了～
```
> 注意 `install.php` 是先 `drop database if exists pikachu` 再重建的，等于把整个库重置一遍。靶场里无所谓，但别在有数据的环境上点这个按钮。
### 4.4 再登录，一次就中
回到 `bf_form.php`，用户名 `admin`、密码 `123456`，点 Login：
```
login success
```
过了。
### 4.5 然后才意识到：这不算爆破
问题就在这儿——**我是知道答案才输的**。
`admin/123456` 这个组合，要么来自页面右上角那个「点一下提示~」，要么来自我刚读过的 `install.php`。这不叫暴力破解，这叫**拿着答案去验证答案**。
真正的爆破应该是：我不知道密码，把 `123456` 混在几百个候选里，让 Intruder 挨个试，最后从"哪条响应不一样"里把它捞出来。
结果一样，练到的东西完全不同。这也是我写这篇复盘的主要原因。
## 五、踩坑记录
| 现象 | 真实原因 | 解决 |
| --- | --- | --- |
| 提交登录后页面崩溃，报 `bind_param() on bool` | 数据库没初始化，`users` 表不存在 | 访问 `install.php` 点「安装/初始化」 |
| 爆破时所有响应"看起来都一样" | 其实全是 `Fatal error` 页面，根本没有成功/失败之分 | 先手动提交一次，确认能看到 `not exists` 再开始爆破 |
| 直接输 `123456` 就成功 | 密码本来就是对的（弱口令），不是爆破出来的 | 想练爆破就别看提示，挂字典跑 |
| 页面"什么都没发生" | 报错被 `@` 抑制，或 `display_errors` 关着 | 查 PHP 错误日志，或临时打开 `display_errors` |
最后一条特别值得说：**爆破工具不会告诉你"目标坏了"**。它只会忠实地把 200 个请求发出去，然后返回 200 个一模一样的错误页。如果事先不确认页面上存在正常的成功/失败回显，很容易把"环境问题"误判成"字典里没这个密码"，然后开始怀疑字典、怀疑工具、怀疑人生。
## 六、我学到了什么
### 6.1 暴力破解成立的前提
不是"有登录框就能爆破"。要同时满足三个条件：
1. **能无限次尝试**——没有验证码、没有账号锁定；
2. **能区分成功与失败**——响应存在可观测的差异；
3. **密码空间够小**——弱口令、常见组合、有规律的命名。
这道题三条全占，所以它才会被放进「暴力破解」模块。
### 6.2 判断结果靠的是"差异"
工具不会告诉你哪条成功，它只给一张表。要自己找差异，常用的四类信号：
| 信号 | 说明 |
| --- | --- |
| 响应长度 | 成功页和失败页的长度通常不同 |
| 状态码 | `302` 跳转 / `200` 正常，可能代表登录成功 |
| 页面关键字 | 如 `login success`、`欢迎 xxx` |
| 响应时间 | 某些逻辑下成功会明显更慢（要查更多数据、写 session 等） |
最省事的是**关键字 + Grep-Match**，因为它是语义级的，不会被页面里的随机内容干扰。
### 6.3 弱口令有多脆弱
`123456` 在几乎所有密码字典里都排前三。这意味着：
- 一个允许无限次尝试的系统，有弱口令账号就等于**没有密码**；
- 攻击者不需要"猜"，只需要"跑"，成本几乎为零；
- 我在靶场里"一次就中"，在真实世界里对应的就是"一次请求就中"。
### 6.4 报错信息是最好的老师
这次能快速定位，全靠 `Fatal error` 里那两个信息：**文件名 + 行号**。
拿到报错后固定做三件事：
1. 看行号指向哪一行；
2. 看这一行在期待什么（`$line_pre` 应该是对象，实际是 `false`）；
3. 往回推一层（`prepare()` 为什么返回 `false`）。
这比"页面打不开，重启一下试试"高效太多。
### 6.5 "知道答案"和"能拿出答案"是两回事
这是这次最大的收获。
看提示、读源码、翻数据库，都能拿到 `admin/123456`。但靶场真正要练的，是**在不知道答案的前提下，用工具把答案找出来**。
差别在真实场景里会被放大：真实目标不会给你提示，源码也不一定拿得到。能复用的只有方法——抓包、定位参数、挂字典、看差异。
## 七、怎么防
针对这题暴露的三个缺失，防御是分层做的：
| 层次 | 措施 | 说明 |
| --- | --- | --- |
| 交互层 | 图形/短信验证码 | 增加单次尝试成本 |
| 账号层 | 失败锁定、延迟重试 | 连续失败 N 次锁定一段时间，或指数退避 |
| 网络层 | 频率限制 | 按 IP + 账号双维度限速，配合 WAF |
| 密码层 | 强密码策略、弱口令检测 | 直接拒绝 `123456` 这类常见密码 |
| 监测层 | 日志与告警 | 同一 IP 高频失败登录要能告警 |
注意：**光加验证码不够**。这个模块后面两关就是在演示"验证码加错位置等于没加"——如果验证码只在前端用 JS 校验，或者服务端只校验一次，那它形同虚设，抓包重放照样能爆。

后面三关都是在这道题的基础上加一层防护，然后让你找这层防护的破绽。所以先把本篇的"抓包 → Intruder → 挂字典 → 看差异"跑熟，后面会顺很多。
