# SQL 注入相关名词手册

> 做题时天天见到、但一直没搞懂的那些词，这一篇一次讲清。
>
> 按"请求从哪来 → 到哪去"的顺序排列，方便对照。

---

## 零、先看一张"名词地图"

**你按回车之后，这些词分别在什么位置：**

```
【你】浏览器地址栏
   |
   |  URL = http://localhost/sqli-labs/Less-1/?id=1' --+
   |         └协议┘ └─主机──┘ └──路径──────┘ └参数┘
   |
   |  HTTP 请求（带着请求头）
   v
【Apache】web 服务器，负责"接到请求，找文件"
   |
   v
【PHP】执行 index.php
   |   ├─ $_GET['id']      接参数
   |   ├─ 字符串拼接       → SQL 语句
   |   ├─ mysqli_query()   发给数据库
   |   ├─ $row             装结果
   |   └─ echo             打印
   v
【MySQL】数据库
   |   └─ 执行 SQL，返回结果集
   v
【HTML 页面】
   |
   |  HTTP 响应
   v
【你看到的内容】
```

**下面按层次逐个解释。**

## 一、网络层

### 1.1 HTTP

| 项目 | 内容 |
| --- | --- |
| 全称 | HyperText Transfer Protocol（超文本传输协议） |
| 一句话 | **浏览器和服务器"说话"用的语言** |
| 特点 | 无状态（每次请求都是独立的） |

**你每次访问网页，浏览器都在发一个 HTTP 请求，服务器回一个 HTTP 响应。**

一个 HTTP 请求长这样：

```
GET /sqli-labs/Less-1/?id=1 HTTP/1.1      ← 请求行
Host: localhost                            ← 请求头
User-Agent: Mozilla/5.0 ...
Cookie: PHPSESSID=abc123
Accept: text/html

（空行）
（请求体，GET 请求一般没有）
```

### 1.2 HTTP 请求方法

| 方法 | 用途 | 参数在哪 |
| --- | --- | --- |
| **GET** | 获取数据 | URL 里（`?id=1`） |
| **POST** | 提交数据 | 请求体里 |
| PUT / DELETE | 修改/删除 | 请求体 |

**sqli-labs 的 Less-1~10 是 GET，Less-11 之后是 POST。**

### 1.3 HTTP 状态码

| 状态码 | 意思 |
| --- | --- |
| **200** | 成功 |
| **302** | 重定向（跳到别的地址） |
| **404** | 找不到 |
| **500** | 服务器内部错误 |

### 1.4 HTTP 请求头（安全里很重要）

| 头 | 内容 | 用途 |
| --- | --- | --- |
| `User-Agent` | 浏览器标识 | **可以被注入**（Less-18） |
| `Referer` | 从哪个页面跳来的 | **可以被注入**（Less-19） |
| `Cookie` | 浏览器带的身份凭证 | **可以被注入**（Less-20） |
| `Host` | 目标域名 | |

### 1.5 URL

| 项目 | 内容 |
| --- | --- |
| 全称 | Uniform Resource Locator |
| 一句话 | **浏览器地址栏那一整串** |

**拆解示例：**

```
http://localhost:80/sqli-labs/Less-1/?id=1#top
└┬─┘   └───┬───┘└┬┘└──────┬──────┘└──┬──┘└─┬─┘
协议      主机   端口   路径        参数   锚点
```

| 部分 | 说明 | 例子 |
| --- | --- | --- |
| **协议** | 用什么方式访问 | `http`、`https` |
| **主机** | 去哪台机器 | `localhost`、`pikachu`、`127.0.0.1` |
| **端口** | 那台机器的哪个门 | `80`（http 默认，常省略）、`3306`（MySQL） |
| **路径** | 要哪个文件 | `/sqli-labs/Less-1/` |
| **参数** | 传给程序的数据 | `?id=1` |
| **锚点** | 页面内跳转 | `#top`（**不发给服务器**） |

### 1.6 参数（Query String）

```
?id=1&name=abc
└┬┘└┬┘└──┬──┘
 ?  参数    &
```

**格式：`?名字=值&名字=值`**

**这是 SQL 注入最常出现的地方。**

### 1.7 URL 编码

特殊字符不能直接放 URL，会被编码：

| 字符 | 编码 |
| --- | --- |
| `'` | `%27` |
| `"` | `%22` |
| 空格 | `%20` 或 `+` |
| `#` | `%23` |
| `&` | `%26` |
| `=` | `%3D` |

**所以你输入 `1' --+`，地址栏会变成 `1%27%20--+`，这是正常的。**

> `#` 必须编码成 `%23`，否则浏览器会把它当锚点，后面的内容不发给服务器。

## 二、服务器层

### 2.1 Apache

| 项目 | 内容 |
| --- | --- |
| 是什么 | **web 服务器软件** |
| 干什么 | 接收 HTTP 请求，找到对应的文件，交给 PHP 执行 |
| 类比 | 餐厅的"迎宾"，负责把客人带到对应餐桌 |

**你的环境里是 Apache 2.4.39。**

### 2.2 PHP

| 项目 | 内容 |
| --- | --- |
| 是什么 | **跑在服务器上的编程语言** |
| 干什么 | 接参数、拼 SQL、查数据库、生成 HTML |
| 谁能看到源码 | **只有服务器**（浏览器拿不到） |

**和 JavaScript 的区别：**

| | PHP | JavaScript |
| --- | --- | --- |
| 跑在哪 | 服务器 | 浏览器 |
| 代码可见吗 | ❌ 不可见 | ✅ F12 全能看到 |
| 对应漏洞 | SQL 注入 | XSS |

### 2.3 LAMP

**一套经典组合：**

| 字母 | 含义 |
| --- | --- |
| L | Linux |
| A | Apache |
| M | MySQL |
| P | PHP |

**Pikachu 和 sqli-labs 都是这套。**

### 2.4 localhost

| 项目 | 内容 |
| --- | --- |
| 意思 | **本机**（就是你自己这台电脑） |
| 等价写法 | `127.0.0.1` |
| 原理 | 系统里 `hosts` 文件把它指向本机 |

**你的 `hosts` 里还加了一行：**

```
127.0.0.1 pikachu
```

**所以访问 `http://pikachu/` 就等于访问本机。**

### 2.5 端口

| 端口 | 服务 |
| --- | --- |
| 80 | HTTP（网页） |
| 443 | HTTPS |
| **3306** | **MySQL** |
| 8080 / 8081 | 常用备用 web 端口 |

**`localhost:80` 和 `localhost` 是一回事（80 可以省略）。**

## 三、数据库层

### 3.1 数据库

> **有组织地存数据的地方。**

**类比：一个 Excel 文件。**

| 数据库概念 | Excel 类比 |
| --- | --- |
| 数据库（database） | 一个 Excel 文件 |
| 表（table） | 一个 sheet |
| 字段（column） | 一列（表头） |
| 行（row） | 一行数据 |

### 3.2 MySQL

| 项目 | 内容 |
| --- | --- |
| 是什么 | 一种**关系型数据库软件** |
| 你的版本 | 5.7.26 |
| 连接信息 | `127.0.0.1:3306`，用户 `root`，密码 `rootroot` |

### 3.3 SQL 语句

> **你跟数据库说话的那句话。**

```sql
SELECT * FROM users WHERE id='1' LIMIT 0,1;
```

**注意：它本来是一段"文本"，发给 MySQL 之后才被解析成指令。**

**SQL 注入就是改这段文本。**

### 3.4 结果集（Result Set）

> **数据库返回的一堆行。**

```
查询：SELECT * FROM users;

结果集：
+----+----------+----------+
| id | username | password |
+----+----------+----------+
| 1  | Dumb     | Dumb     |
| 2  | Angelina | I-kill-you|
| 3  | Dummy    | p@ssword |
+----+----------+----------+
```

**PHP 拿到的就是这个"表格"。**

### 3.5 information_schema

| 项目 | 内容 |
| --- | --- |
| 是什么 | MySQL **自带的"元数据库"** |
| 存什么 | 所有库、表、字段的**名字** |
| 用途 | 注入时用它"查目录" |

**两张关键表：**

| 表 | 存什么 | 关键字段 |
| --- | --- | --- |
| `information_schema.tables` | 所有表 | `table_schema`（库名）、`table_name`（表名） |
| `information_schema.columns` | 所有字段 | `table_name`、`column_name` |

**类比：图书馆的"检索系统"，告诉你有哪些书、在哪个书架。**

### 3.6 库、表、字段、行

```
数据库 security
  └── 表 users
        ├── 字段 id
        ├── 字段 username
        └── 字段 password

        行 1: 1  | Dumb     | Dumb
        行 2: 2  | Angelina | I-kill-you
```

## 四、PHP 代码层

### 4.1 `<?php ... ?>`

**PHP 代码的"边界标记"。**

```html
<h1>标题</h1>
<?php echo "这是 PHP 输出的"; ?>
<p>普通 HTML</p>
```

**只有 `<?php ?>` 中间的内容会被当 PHP 执行。**

### 4.2 变量 `$xxx`

```php
$id = 1;
$name = "pikachu";
```

**PHP 里变量必须以 `$` 开头。**

### 4.3 `$_GET` 和 `$_POST`

| 超全局变量 | 收什么 | 从哪来 |
| --- | --- | --- |
| `$_GET['id']` | GET 参数 | URL 的 `?id=` |
| `$_POST['id']` | POST 参数 | 请求体 |
| `$_COOKIE['x']` | Cookie | 请求头 |
| `$_SERVER['HTTP_USER_AGENT']` | UA | 请求头 |

**`$_GET['id']` 就是"从 URL 里取 id 的值"。**

```php
// URL: ?id=1'
$id = $_GET['id'];      // $id 现在等于 "1'"
```

### 4.4 `mysqli_query()`

```php
$result = mysqli_query($con1, $sql);
```

**作用：把 SQL 语句发给 MySQL 执行。**

| 参数 | 是什么 |
| --- | --- |
| `$con1` | 数据库连接（已经连好的"电话线"） |
| `$sql` | SQL 语句文本 |

### 4.5 `mysqli_fetch_array()`

```php
$row = mysqli_fetch_array($result);
```

**作用：从结果集里"取一行"，变成数组。**

```
$result（结果集）           $row（一行）
  +----+-------+          +------------------+
  | 1  | Dumb  |   -->    | id => 1          |
  | 2  | Angel  |          | username => Dumb |
  +----+-------+          | password => Dumb |
                          +------------------+
```

**每次调用取一行，取完返回 null。**

### 4.6 `$row`

| 项目 | 内容 |
| --- | --- |
| 是什么 | **一个数组，装着一行数据** |
| 怎么取值 | `$row['username']` |

**这是"数据在 PHP 手里的最后形态"。**

**如果没人 `echo` 它，它就消失了。**

### 4.7 `echo`

```php
echo "hello";
echo $row['username'];
```

**作用：把内容打印到 HTML 页面上。**

**⭐ 这是数据流里的"出口"。**

**有 `echo $row[...]` → 能看到数据（Less-1~4）**
**没有 → 看不到（Less-5）**

### 4.8 `print_r()`

```php
print_r(mysqli_error($con1));
```

**作用：打印变量的内容（调试用）。**

**Less-5 用它打印 SQL 报错——这就是报错注入的"出口"。**

### 4.9 `mysqli_error()`

```php
mysqli_error($con1)
```

**作用：返回最近一次 SQL 操作的错误信息。**

**注入时最希望看到的函数——它会把你的 payload 报出来。**

## 五、注入术语

### 5.1 payload

| 项目 | 内容 |
| --- | --- |
| 意思 | **"有效载荷"**，指你注入的那段恶意内容 |
| 例子 | `1' union select 1,2,3 --+` |

**它是"参数值的一部分"。**

### 5.2 闭合

| 项目 | 内容 |
| --- | --- |
| 意思 | **把后台留下的符号"补齐"，让语法重新合法** |
| 例子 | 后台是 `id='$id'`，你输入 `1'` 就闭合了引号 |

**类比：别人写了一半的括号，你把它补完。**

### 5.3 注释

| 写法 | 说明 |
| --- | --- |
| `-- ` | SQL 注释，**后面必须有空格** |
| `--+` | URL 里用 `+` 代替空格 |
| `#` | MySQL 注释，URL 里写 `%23` |
| `/* */` | 块注释 |

**作用：把后面多余的 SQL 代码"废掉"。**

### 5.4 回显位

| 项目 | 内容 |
| --- | --- |
| 意思 | **页面上"能显示数据的位置"** |
| 判断 | 源码里有没有 `echo $row[...]` |

**有回显位 → 能用 union 直接把数据塞进去。**
**没回显位 → 只能用盲注或报错注入。**

### 5.5 联合注入（union）

```sql
?id=-1' union select 1,2,3 --+
```

**作用：把你自己写的查询结果，拼到原查询后面，显示在页面上。**

**前提：有回显位 + 列数一致。**

### 5.6 报错注入

```sql
?id=1' and updatexml(1,concat(0x7e,database()),1) --+
```

**作用：故意让 SQL 报错，把数据塞进错误信息里。**

**前提：页面会打印 `mysqli_error()`。**

### 5.7 布尔盲注

```sql
?id=1' and 1=1 --+    → 有内容（真）
?id=1' and 1=2 --+    → 空白（假）
```

**作用：靠"页面有没有内容"来回答是/否问题，一个字一个字猜。**

**前提：页面有两种可观察状态。**

### 5.8 时间盲注

```sql
?id=1' and sleep(3) --+
```

**作用：靠"页面响应快慢"来判断真假。**

**前提：连"有没有内容"都看不出来。**

### 5.9 `group_concat()`

```sql
select group_concat(username) from users;
-- 结果：Dumb,Angelina,Dummy,...
```

**作用：把多行结果拼成一行。**

**为什么需要：页面一次只能显示一行，不拼就只看得到第一条。**

### 5.10 `0x3a` / `0x7e`

**十六进制表示的字符。**

| 十六进制 | 字符 | 用途 |
| --- | --- | --- |
| `0x3a` | `:` | `group_concat(username,0x3a,password)` |
| `0x7e` | `~` | `concat(0x7e,database(),0x7e)` 当标记 |

**为什么用十六进制：省得再写一层引号，避免把 SQL 搞乱。**

### 5.11 ASCII / substr / length

| 函数 | 作用 | 例子 |
| --- | --- | --- |
| `length()` | 求长度 | `length('security')` = 8 |
| `substr()` | 截取字符 | `substr('security',1,1)` = `s` |
| `ascii()` | 转 ASCII 码 | `ascii('s')` = 115 |

**三者配合，就是盲注的核心：**

```sql
ascii(substr(database(),1,1))=115
```

### 5.12 隐式类型转换

**MySQL 会把字符串当数字比较。**

| 字符串 | 转成数字 |
| --- | --- |
| `'1abc'` | `1` |
| `'1) -- '` | `1` |
| `'-1 union...'` | `-1` |

**后果：可能"意外查到数据"，让你误判闭合方式。**

**判断闭合要看"报错是否消失"，不是"有没有数据"。**

## 六、防御术语

### 6.1 预编译 / 参数化查询

```php
$stmt = $mysqli->prepare("SELECT * FROM users WHERE id=?");
$stmt->bind_param('s', $id);
$stmt->execute();
```

| 项目 | 内容 |
| --- | --- |
| 原理 | SQL 结构先定死，`?` 只等着填"值" |
| 效果 | 输入永远是数据，进不了"代码区" |

**这是 SQL 注入的根本解。**

### 6.2 `bind_param()`

```php
$stmt->bind_param('s', $id);
```

| 参数 | 意思 |
| --- | --- |
| `'s'` | string（字符串） |
| `'i'` | integer（整数） |
| `'d'` | double（浮点） |

### 6.3 转义（次要手段）

```php
$id = mysqli_real_escape_string($link, $id);
```

**给特殊字符加反斜杠，`'` 变成 `\'`。**

**注意：可以被"宽字节注入"绕过（Less-32）。**

### 6.4 WAF

| 项目 | 内容 |
| --- | --- |
| 全称 | Web Application Firewall（web 应用防火墙） |
| 干什么 | 拦恶意请求（含 SQL 注入特征） |
| 局限 | 能被编码、变形、分块绕过 |

## 七、速查表

### 7.1 一句话版

| 名词 | 一句话 |
| --- | --- |
| HTTP | 浏览器和服务器说话的语言 |
| URL | 地址栏那一串 |
| payload | 你注入的坏东西 |
| Apache | 接请求、找文件的服务器软件 |
| PHP | 跑在服务器上的语言 |
| `$_GET` | 从 URL 取参数 |
| SQL 语句 | 跟数据库说的那句话 |
| MySQL | 存数据、执行 SQL 的软件 |
| 结果集 | 数据库返回的一堆行 |
| `$row` | PHP 手里的一行数据 |
| `echo` | 打印到页面的语句（**出口**） |
| 回显位 | 页面上能显示数据的位置 |
| 闭合 | 把后台的符号补齐 |
| 注释 | 把多余的代码废掉 |
| union | 拼一条自己的查询进去 |
| 盲注 | 只能问是/否 |
| information_schema | MySQL 自带的"目录表" |
| group_concat | 多行拼一行 |
| 预编译 | 让输入永远是数据 |

### 7.2 数据流速记

```
URL 参数
  → $_GET
  → 拼成 SQL 语句
  → mysqli_query
  → MySQL 执行
  → 结果集
  → $row
  → echo
  → 页面
```

**记住这条链，任何一关都能定位问题在哪。**

### 7.3 看到这些词该怎么想

| 看到 | 想什么 |
| --- | --- |
| `$_GET['id']` | 注入点在这 |
| 字符串拼接 | 漏洞根源在这 |
| `echo $row[...]` | **有回显位** |
| `mysqli_error()` | **能用报错注入** |
| `if($row)` 只有固定 echo | **只能盲注** |
| `prepare` + `?` | 安全写法 |

---

## 八、总结

> **SQL 注入这条链上，每一个名词都对应一个"环节"。**
>
> **你只要知道：数据从 URL 进来 → PHP 拼成 SQL → 数据库执行 → 结果放 `$row` → `echo` 决定能不能看到。**

**这条链上任何一环"偷懒"，都会变成漏洞。**
