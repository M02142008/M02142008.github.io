# 越权 概述 笔记

> 越权（Over Permission）不是"绕过登录"，而是——**登录了，但做了超出自己权限的事。**

## 二、两种越权

### 2.1 水平越权（横向）

> **同一级别的用户，A 能看到/操作 B 的数据。**

例子：

- 你查订单 `?id=1001`，改成 `?id=1002` 看到了别人的订单
- 你改资料，`username` 参数改成别人，改掉了别人的信息

**特点：身份没变，只是"换了个人"。**

### 2.2 垂直越权（纵向）

> **低权限用户，做了高权限才能做的事。**

例子：

- 普通用户直接访问 `/admin/user_list.php`
- 普通用户调用了"删除用户"的接口
- 前端把"添加用户"按钮藏了，但接口没校验权限

**特点：身份没变，只是"做了更高的事"。**

---

## 三、两者的区别

| | 水平越权 | 垂直越权 |
| --- | --- | --- |
| 攻击者身份 | 普通用户 | 普通用户 |
| 目标 | **同级别的其他人** | **更高权限的功能** |
| 本质 | 数据隔离没做好 | 功能权限没做好 |
| 例子 | 看别人的订单 | 进后台管理 |

---

## 四、越权的成因

| 原因 | 说明 |
| --- | --- |
| **只在前端做权限控制** | 按钮藏起来，接口没校验 |
| **信任客户端传的 ID** | `?username=xxx` 直接用，不校验是不是本人 |
| **只校验登录，不校验权限** | `if (!login()) redirect;` 但没判断 level |
| **不同接口校验不一致** | 列表页校验了，详情页没校验 |

**核心：把"你应该只能做什么"交给了客户端决定。**

---

## 五、怎么发现越权

| 方法 | 操作 |
| --- | --- |
| **改 ID** | `?id=1` → `?id=2` |
| **改用户名** | `?username=me` → `?username=other` |
| **直接访问** | 普通用户手动打开 `/admin/xxx` |
| **抓包改参数** | 前端隐藏的字段、接口里多传一个 `role=admin` |
| **对比响应** | 权限不同时，返回内容/状态码是否不同 |

---

## 六、防御方向

| 措施 | 说明 |
| --- | --- |
| **服务端校验权限** | 每个接口都判断"当前用户能不能做这件事" |
| **不信任客户端 ID** | 数据归属从 session 取，不从参数取 |
| **统一的权限中间件** | 别每个接口各写一套 |
| **RBAC / ABAC** | 基于角色/属性的访问控制 |
| **越权测试纳入流程** | 开发和测试都要测 |

### 6.1 最典型的错误写法

```php
// 错误：用参数里的 username
$username = $_GET['username'];
$query = "select * from member where username='$username'";
```

### 6.2 正确写法

```php
// 正确：从 session 取
$username = $_SESSION['user']['username'];
$query = "select * from member where username=?";
```

**或者至少校验：**

```php
if ($_GET['username'] !== $_SESSION['user']['username']) {
    exit('无权查看');
}
```

---

## 七、总结

| 要点 | 内容 |
| --- | --- |
| 水平越权 | 同级别，看/改别人的数据 |
| 垂直越权 | 低权限，做高权限的事 |
| 成因 | 权限校验缺失或只在客户端 |
| 防御 | 服务端校验 + 不信任客户端 ID |

**一句话**：

> **"登录了"不等于"有权做这件事"——这两件事必须分开校验。**
