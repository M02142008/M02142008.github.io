# 水平越权 通关笔记

> 你登录的是自己的账号，但"查谁的信息"这件事，**是 URL 参数说了算。**

---

## 一、环境与目标

| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 关卡位置 | Over Permission → 水平越权 |
| 登录页 | `http://pikachu/vul/overpermission/op1/op1_login.php` |
| 目标页 | `http://pikachu/vul/overpermission/op1/op1_mem.php` |
| 提交方式 | **POST** 登录，**GET** 查询 |
| 测试账号 | `vince` / `123456`（member 表，密码都是 123456） |
| 目标 | 用 vince 的账号看到别人的信息 |

---

## 二、我的解题步骤

### 步骤 1：登录自己的账号

打开登录页，输入 `vince` / `123456`。

进入个人信息中心：

```
欢迎来到个人信息中心

[点击查看个人信息]
```

### 步骤 2：点按钮，看请求

点「点击查看个人信息」，地址变成：

```
op1_mem.php?username=vince&submit=点击查看个人信息
```

页面显示 vince 的信息。

**注意：`username` 在 URL 里，而且是明文。**

### 步骤 3：看源码，发现问题

```php
if(isset($_GET['submit']) && $_GET['username']!=null){
    //没有使用session来校验,而是使用的传进来的值，权限校验出现问题,这里应该跟登录态关系进行绑定
    $username=escape($link, $_GET['username']);
    $query="select * from member where username='$username'";
    $result=execute($link, $query);
    ...
}
```

**作者的注释写得很明白：**

> 没有使用 session 来校验，而是使用的传进来的值，权限校验出现问题，这里应该跟登录态关系进行绑定

**服务端用的是 `$_GET['username']`，不是 `$_SESSION`。**

### 步骤 4：改成别人的用户名

把 URL 里的 `vince` 改成 `allen`：

```
op1_mem.php?username=allen&submit=点击查看个人信息
```

### 步骤 5：结果

**页面显示了 allen 的信息。**

我实测：

| 请求 | 页面显示 |
| --- | --- |
| `username=vince` | 姓名:vince，邮箱:vince@pikachu.com |
| `username=allen` | **姓名:allen，邮箱:allen@pikachu.com** |

**全程登录的是 vince 的账号。**

## 三、原理分析

### 3.1 完整的漏洞链

```
1. 用户登录 → session 里存了 username=vince
2. 页面表单里有个 hidden 字段 username=vince
3. 点击提交 → GET ?username=vince
4. 服务端：用 $_GET['username'] 查数据库
5. 攻击者：把 URL 里的 vince 改成 allen
6. 服务端：用 $_GET['username']=allen 查数据库 → 返回 allen 的信息
```

**问题在第 4 步：服务端"信了"客户端传来的身份。**

### 3.2 表单里的隐藏字段是摆设

```html
<input type="hidden" name="username" value="<?php echo $_SESSION['op']['username']; ?>" />
```

**隐藏字段对用户不可见，但对攻击者完全可见、可改。**

**前端隐藏 ≠ 安全。**

### 3.3 正确的写法

```php
// 应该这样：身份从 session 取
$username = $_SESSION['op']['username'];
```

**这样用户改 URL 也没用——服务端根本不看 URL 里的 username。**

## 四、知识点与笔记

### 4.1 水平越权的判断

| 步骤 | 操作 |
| --- | --- |
| 1 | 找一个"查看/修改某条数据"的接口 |
| 2 | 看参数里有没有 id / username / uid |
| 3 | 改成别的值 |
| 4 | 看能不能看到别人的数据 |

### 4.2 水平越权常见的参数

| 参数 | 例子 |
| --- | --- |
| `id` | `?id=1` → `?id=2` |
| `uid` | `?uid=1001` → `?uid=1002` |
| `username` | `?username=vince` → `?username=allen` |
| `order_id` | `?order_id=20240001` |
| `file_id` | `?file_id=abc` |

**凡是"能定位到某条数据"的参数，都值得试。**

### 4.3 隐藏字段为什么不可靠

```html
<input type="hidden" name="username" value="vince">
```

攻击者可以：

- F12 改 value
- 直接改 URL
- 用 Burp 改包
- 用脚本直接发

**隐藏字段只是"界面上不显示"，不是"传不过去"。**

### 4.4 和 SQL 注入的区别

| | 水平越权 | SQL 注入 |
| --- | --- | --- |
| 怎么拿数据 | **合法查询，换了参数** | 篡改 SQL |
| 需要注入吗 | **不需要** | 需要 |
| 难发现吗 | 难（看起来很正常） | 相对容易（有报错） |

**越权是"用合法功能做非法的事"，更难被 WAF 发现。**

---

## 五、和垂直越权的区别

| | 水平越权（本关） | 垂直越权 |
| --- | --- | --- |
| 攻击者 | 普通用户 | 普通用户 |
| 目标 | **同级别的别人的数据** | **更高权限的功能** |
| 关键点 | 数据归属没校验 | 功能权限没校验 |
| 例子 | 查 allen 的信息 | 进后台管理 |

## 六、防御怎么写

### 6.1 身份从 session 取

```php
$username = $_SESSION['op']['username'];
$stmt = $link->prepare("select * from member where username=?");
$stmt->bind_param('s', $username);
$stmt->execute();
```

**这是最彻底的修法。**

### 6.2 如果一定要传 ID，做归属校验

```php
$id = intval($_GET['id']);
$stmt = $link->prepare("select * from member where id=? and username=?");
$stmt->bind_param('is', $id, $_SESSION['op']['username']);
```

**把"是我的"这个条件写进 SQL。**

### 6.3 不要依赖前端隐藏字段

**任何"前端不显示"的东西，攻击者都能看到、都能改。**

---

## 七、总结

| 要点 | 内容 |
| --- | --- |
| 这关教什么 | 身份由客户端参数决定 |
| 关键点 | 服务端用 `$_GET['username']` 而不是 `$_SESSION` |
| payload | `?username=allen` |
| 实测 | vince 登录，看到 allen 的信息 |
| 修复 | 身份从 session 取 |

**一句话**：

> **你登录的是自己，但"看谁的数据"如果由 URL 决定——那就是水平越权。**
