# SQL 语言基础

> 做 SQL 注入之前，得先搞清楚 SQL 到底是个什么东西。
>
> 这篇不涉及攻击，只讲"SQL 是什么、怎么读、为什么它能被注入"。

---

## 一、SQL 是什么

**SQL = Structured Query Language（结构化查询语言）。**

一句话：

> **它是一门专门用来"跟数据库说话"的语言。**

你想从数据库里拿数据、改数据、建表，都得用 SQL 说。

```sql
SELECT username, password FROM users WHERE id = 1;
```

**翻译成中文：从 users 表里，把 id 等于 1 的那一行的 username 和 password 给我。**

---

## 二、它和 Python / JS 的区别

### 2.1 一句话区别

| | SQL | Python / JavaScript |
| --- | --- | --- |
| 类型 | **声明式**（Declarative） | **命令式**（Imperative） |
| 你写的是 | **要什么** | **怎么做** |

### 2.2 点菜的比喻

**SQL 像点菜：**

> "来一份宫保鸡丁"

你只说需求，**厨房（数据库）自己决定怎么炒、先放什么后放什么。**

**Python 像自己下厨：**

> "先热油 → 放葱姜 → 下鸡丁 → 翻炒三分钟 → 装盘"

**每一步都得你自己写。**

### 2.3 代码对比

**SQL（声明式）：**

```sql
SELECT name FROM users WHERE age > 18 ORDER BY age;
```

**Python（命令式）：**

```python
result = []
for user in users:
    if user['age'] > 18:
        result.append(user['name'])
result.sort(key=lambda u: u['age'])
```

**同一个需求，SQL 一句话，Python 要四行。**

### 2.4 它算"编程语言"吗

| 能力 | SQL | Python |
| --- | --- | --- |
| 查询数据 | ✅ | ✅ |
| 数学计算 | ✅ | ✅ |
| 写网页 | ❌ | ✅ |
| 写操作系统 | ❌ | ❌ |
| 任意复杂逻辑 | ⚠️ 有限（存储过程可补） | ✅ |

**严格说它是"查询语言"，不是"通用编程语言"。**

**但在安全语境下，它就是"代码"** —— 因为：

> **只要一段文本会被"解析并执行"，它就是代码。**

## 三、一条 SQL 的组成

### 3.1 完整的句子

```sql
SELECT username, password
FROM users
WHERE id = 1
ORDER BY id DESC
LIMIT 0, 1;
```

### 3.2 逐段拆开

| 关键字 | 作用 | 中文 |
| --- | --- | --- |
| `SELECT` | 要哪些列 | 我要什么 |
| `FROM` | 从哪张表 | 去哪找 |
| `WHERE` | 筛选条件 | 只要满足条件的 |
| `ORDER BY` | 排序 | 按什么排 |
| `LIMIT` | 限制行数 | 只要前几条 |

**这五个关键字就覆盖了 90% 的查询。**

### 3.3 常见的其他关键字

| 关键字 | 作用 |
| --- | --- |
| `UNION` | 把两个查询结果拼起来 |
| `GROUP BY` | 分组 |
| `JOIN` | 多表关联 |
| `INSERT INTO` | 插入数据 |
| `UPDATE ... SET` | 修改数据 |
| `DELETE FROM` | 删除数据 |
| `CREATE TABLE` | 建表 |
| `DROP DATABASE` | 删库 |

---

## 四、SQL 的四类语句

| 类别 | 全称 | 代表语句 | 干什么 |
| --- | --- | --- | --- |
| **DQL** | Data Query Language | `SELECT` | 查数据 |
| **DML** | Data Manipulation Language | `INSERT` / `UPDATE` / `DELETE` | 改数据 |
| **DDL** | Data Definition Language | `CREATE` / `ALTER` / `DROP` | 改结构 |
| **DCL** | Data Control Language | `GRANT` / `REVOKE` | 改权限 |

**注入攻击最常利用的是 DQL（查），危害最大的是 DDL（删库）。**

## 五、为什么 SQL 是"代码"

### 5.1 有语法，就会报错

```sql
SELECT * FROM users WHERE id = '1'
```

正常。

```sql
SELECT * FROM users WHERE id = '1''
```

报错：

```
You have an error in your SQL syntax ... near ''1'' at line 1
```

**写错一个引号就报错——这就是"语言"的特征，不是"字符串"。**

### 5.2 有解析器

```
你写的 SQL 文本
      ↓
数据库的解析器（Parser）
      ↓
理解成"语法树"
      ↓
执行
```

**文本进去，动作出来。**

### 5.3 三种"被解析的文本"

| 文本 | 被谁解析 | 变成什么 |
| --- | --- | --- |
| `<script>alert(1)</script>` | 浏览器 | JavaScript 执行 |
| `SELECT * FROM users` | 数据库 | SQL 执行 |
| `ping 127.0.0.1` | 操作系统 | 命令执行 |

**这就是"注入类漏洞"能成立的物理基础。**

## 六、和注入的关系：值区与代码区

### 6.1 后台的写法

```php
$sql = "SELECT * FROM users WHERE id='$id' LIMIT 0,1";
```

拼接后：

```sql
SELECT * FROM users WHERE id=' ___ ' LIMIT 0,1
                              ^^^^^
                           你的输入
```

### 6.2 两个区

```
SELECT * FROM users WHERE id = ' .......... ' LIMIT 0,1
                               ^^^^^^^^^^^^   ^^^^^^^^^^^^
                                  值区            代码区
```

| 区域 | 数据库怎么看 |
| --- | --- |
| **值区**（引号内） | 数据，写得再花也是字符串 |
| **代码区**（引号外） | 语法，会被执行 |

### 6.3 注入就一句话

> **把引号提前关掉，然后站到引号外面写字。**

```sql
-- 你的输入：1' union select 1,2,3 --+
SELECT * FROM users WHERE id='1' union select 1,2,3 --+ ' LIMIT 0,1
                            ^^^^^^^^^^^^^^^^^^^
                              你在代码区写的话
```

## 八、总结

| 要点 | 内容 |
| --- | --- |
| SQL 是什么 | 跟数据库说话的声明式查询语言 |
| 和 Python 的区别 | 只说"要什么"，不说"怎么做" |
| 一条查询的结构 | SELECT / FROM / WHERE / ORDER BY / LIMIT |
| 为什么是"代码" | 有语法、有解析器、会执行 |
| 和注入的关系 | 输入越界，从值区进入代码区 |

**一句话**：

> **SQL 不是用来"算"的，是用来"问"的。**
> **但它问得足够精确，精确到可以被篡改。**
