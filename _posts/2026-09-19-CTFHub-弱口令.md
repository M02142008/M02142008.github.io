# CTFHub Writeup - 弱口令（POST 爆破）

## 题目类型

Web 基础、弱口令爆破、POST 表单爆破

## 题目描述

题目给出一个简单的账号密码登录界面，前端无验证码、无防爆破机制。
账号已知为固定值，密码未知，需要通过**POST 暴力破解**尝试出正确密码，登录成功后获取 Flag。

## 解题思路

1. 打开题目环境，观察登录表单为**POST 提交数据**
2. 抓包观察数据包提交格式：账号、密码参数明文提交
3. 无拦截、无次数限制、无验证码，典型弱口令爆破场景
4. 使用字典对 password 参数进行批量爆破
5. 依据响应包长度 / 内容差异，判断登录成功，拿到 Flag

## 详细解题过程

### 1. 抓包分析请求数据包

访问登录页面，随便输入账号密码点击登录，抓包得到核心 POST 数据：

```
username=admin&password=xxxx
```

可以确定：

- 提交方式：POST
- 参数名：username、password
- 题目固定用户名，只需要爆破密码

### 2. 分析响应差异

错误密码时：页面返回 **登录失败** 固定文本，响应长度短、内容统一。
正确密码时：页面跳转 / 返回成功页面，返回内容长度明显不同，包含 Flag。

### 3. 爆破操作（Burp Suite 通用流程）

1. 将数据包发送到 Intruder 模块
2. 固定 username 参数，给 password 设置爆破变量
3. 加载常见弱口令字典（top 弱口令字典）
4. 开始爆破，通过 **Length 长度排序** 筛选异常响应包
5. 找到长度不同的数据包，查看响应内容，得到正确密码与 Flag

### 4. 登录拿到 Flag

使用爆破得到的正确密码登录页面，页面直接展示题目 Flag，解题完成。

## 踩坑记录（新手必看）

1. **GET/POST 混淆**
新手容易直接在 URL 拼接参数尝试，本题是 POST 表单，GET 方式无法生效，必须抓包 POST 爆破。
2. **不会判断成功包**
不要肉眼逐个看数据包，直接按照响应**长度排序**，唯一不一样的那条就是正确密码。
3. **字典过小跑不出来**
自带简易字典可能缺漏密码，建议使用通用 web 弱口令字典。

## 知识点总结 & 学习笔记

1. **弱口令漏洞原理**
开发者未设置复杂密码、未开启登录次数限制、无验证码防护，导致攻击者可以批量遍历密码登录后台。
2. **POST 爆破核心逻辑**
通过自动化工具批量替换密码参数，利用**返回包差异**判断是否登录成功，是 Web 入门最核心的爆破思路。
3. **防御方式**

- 设置强复杂度密码
- 增加登录次数锁定机制
- 添加图形 / 短信验证码
- 增加 IP 访问频率限制
