# XSS 做题方法总结：四步法、我的理解，以及它在现实里到底用来干什么
> 打完全部反射型 XSS 之后整理的笔记。前半部分是能直接套用的四步法和 payload 小抄；后半部分是我对 XSS 本身的理解——包括我一开始那些错得离谱的判断，以及它在现实中到底被用来做什么。
---
## 一、通用四步（以后每关都能套用）
| 步骤 | 做什么 | 目的 |
| --- | --- | --- |
| 1. 找入口 | 页面上有没有输入框？URL 里有没有 `?xxx=` | 找到"能塞东西进去"的地方 |
| 2. 测回显 | 输入 `abc123`，看它出现在页面哪里 | 确认输入会不会被显示出来 |
| 3. 试标签 | 输入 `<b>abc</b>` | 判断尖括号有没有被过滤 |
| 4. 上 payload | 换成 `<script>alert(1)</script>` | 看能不能执行 |
### 第 3 步是核心技巧，叫"差分测试"
| 页面显示 | 说明 |
| --- | --- |
| **abc**（加粗了） | 标签被解析了 ✅ 有戏 |
| `<b>abc</b>`（连尖括号一起显示） | 被转义了 ❌ 这条路堵死 |
用 `<b>` 而不是 `<script>`，是因为 `<b>` 加粗了你一眼就能看出来，而且很少有网站会过滤它。
更重要的原因：`<b>` **没有副作用**。它不会弹窗打断你，不会跳转，不会报错，就是一个纯粹的"探针"。

## 二、你之前看到的东西，到底是什么意思
### 2.1 `<script>alert(1)</script>` 拆开看
```html
<script>alert(1)</script>
└──┬──┘ └──┬──┘ └───┬───┘
 开始标签   代码内容  结束标签
```
| 部分 | 意思 |
| --- | --- |
| `<script>` | 告诉浏览器："下面这段是代码，要执行" |
| `alert(1)` | 代码内容：弹出一个写着 `1` 的框 |
| `</script>` | 代码到此结束 |
### 2.2 `<img src=x onerror=alert(1)>` 拆开看
```html
<img src=x onerror=alert(1)>
```
| 部分 | 意思 |
| --- | --- |
| `<img>` | 插入一张图片 |
| `src=x` | 图片地址是 `x`（不存在，所以加载会失败） |
| `onerror=` | 加载失败时执行什么 |
| `alert(1)` | 失败时弹窗 |
**为什么用它？** 因为很多网站会过滤 `<script>`，但不管 `<img>`。
还有个额外好处：**碎图本身就是"标签被解析了"的可见证据**——比等弹窗可靠。
### 2.3 URL 里那些符号
| 你看到的 | 其实是 | 为什么 |
| --- | --- | --- |
| `%3C` | `<` | URL 里直接写尖括号有歧义，要编码 |
| `%3E` | `>` | 同上 |
| `%27` | `'` | 同上 |
| `%20` | 空格 | 同上 |
| `maxlength="20"` | 输入框最多 20 个字 | 前端限制，改 URL 就绕过 |

## 三、这一关的操作，翻译成人话
| 我让你做的 | 实际在干嘛 |
| --- | --- |
| 打开页面 | 找到输入入口 |
| 输入 `kobe` | 看正常功能是什么样 |
| 输入 `test` | 确认输入会原样显示在页面里 |
| 改地址栏 | 因为输入框限制 20 个字，payload 有 25 个，塞不进去 |
| 看到碎图 / 红屏 | 说明标签被解析了，通关 |

## 四、怎么判断"成功了"
| 页面表现 | 结论 |
| --- | --- |
| 显示文字 `<script>alert(1)</script>`（有尖括号） | 被转义，失败 |
| 弹出对话框 | 成功 |
| 出现碎图 / 页面变红 / 标题改变 | 成功（代码被执行了，只是没弹窗） |
| 页面完全没变化 | 检查参数名、payload 有没有被截断 |
**核心：不要只等弹窗。** 弹窗只是最直观的表现，不是唯一标准。
---
## 五、payload 小抄（以后直接用）
| payload | 作用 | 什么时候用 |
| --- | --- | --- |
| `<script>alert(1)</script>` | 标准弹窗 | 没有过滤时 |
| `<img src=x onerror=alert(1)>` | 借坏图片弹窗 | `<script>` 被过滤时 |
| `<svg/onload=alert(1)>` | SVG 加载时执行 | 需要更短的 payload 时 |
| `<script>document.body.style.background='red'</script>` | 页面变红 | 弹窗被浏览器禁用时 |
| `<script>document.title='XSS'</script>` | 改标签页标题 | 同上 |
| `<b>test</b>` | 只加粗，不执行 | 探测有没有过滤（第一步用） |
---
## 六、遇到限制怎么办
| 限制 | 绕过方法 |
| --- | --- |
| 输入框 `maxlength` | 直接改 URL，或者 F12 删掉这个属性 |
| `<script>` 被过滤 | 换 `<img>`、`<svg>`、`<body onload=>` |
| 大小写被拦 | 试 `<ScRiPt>` |
| 双引号被转义 | 用不带引号的写法 `onerror=alert(1)` |
---
## 七、一句话记住整套方法
> **先测"尖括号能不能活"，再决定"用什么 payload"。**
>
> 尖括号活 → 直接上标签
> 尖括号死 → 这关大概率不是 XSS，或者要换编码/绕过方式

# 八、我对 XSS 的理解
前面是"怎么做"，这一节是"它到底是什么"。这部分我改了三次才想明白。
## 8.1 它到底是什么
教科书上的定义是：
> XSS（跨站脚本）是指攻击者往 Web 页面里插入恶意 Script 代码，当用户浏览该页时，嵌入其中的 Script 代码会被执行，从而达到恶意攻击用户的目的。
但我更愿意用一句话概括：
> **你写的代码，住进了别人的网站里，然后在那个人面前跑了起来。**
关键在于"**住进**"——它不是从外面攻击服务器，而是变成了页面的一部分。
## 8.2 三个我一开始搞错的地方
### 误解一：XSS 是"改掉对方的网站"
**错。** 你改不了服务器，改不了数据库。
你改的是**"这个页面在某个用户浏览器里呈现的样子"**。刷新一下，服务器还会把原样的页面发回来。
### 误解二：XSS 的危害是"弹个框"
**错。** `alert(1)` 只是"我成功了"的信号弹，它证明代码能跑。
真实的攻击代码不会弹窗，它会**安静地**把你的 Cookie 发走。
### 误解三：没弹窗就是失败了
**错。** 这是我这次踩的最大的坑。`<script>` 标签本身不产生任何可见文字，所以页面看起来"什么都没发生"，但代码其实已经执行了。
## 8.3 我的理解变化过程
| 阶段 | 我的理解 | 哪里不对 |
| --- | --- | --- |
| 第一阶段 | "XSS 是把网页改掉" | 那是篡改，不是 XSS |
| 第二阶段 | "XSS 是让页面执行 JS" | 对了，但没抓住要害 |
| 第三阶段 | "XSS 是**借用网站的信任**" | 这层才算通了 |
第三阶段是关键：**你的代码不是"外来者"，它享有和网站自己代码完全相同的权限。**
## 8.4 一个比喻：借壳
我后来想明白，XSS 就像**借壳**：
> 你不是撬锁进店，你是穿上了店员的制服，站到了柜台后面。
>
> 顾客推门进来，看到制服就信了——他信的是"这家店"，不是"你这个人"。
浏览器也一样：它信任这个页面的**来源**（同源），于是无条件执行页面里所有的脚本——**不管这段脚本是网站自己写的，还是攻击者塞进来的。**
这就是为什么 XSS 难防：**它利用的不是漏洞，是信任。**
## 8.5 三种类型
| 类型 | 存在哪 | 谁中招 | 危害 |
| --- | --- | --- | --- |
| **反射型** | 不存，服务器原样返回 | 只有点这个链接的人 | 中 |
| **存储型** | 存进数据库 | **所有访问这个页面的人** | **高** |
| **DOM 型** | 不经过服务器 | 看前端 JS 怎么写 | 中 |
- **反射型**：payload 放在 URL 里，骗人点一下。一次一个。
- **存储型**：payload 存进数据库（比如留言板），之后每个打开页面的人都中招。**这是最危险的一种**，因为它能自己传播。
- **DOM 型**：服务器完全不知情，是前端 JS 自己把地址栏的内容拼进了页面。

# 九、XSS 在现实里到底用来干什么
学完原理我一直在想：弹个框有什么用？后来查了资料才明白，`alert` 只是靶场里的演示，真实场景完全是另一回事。
## 9.1 攻击者的视角
| 目的 | 手法 | 后果 |
| --- | --- | --- |
| **盗取会话** | `document.cookie` 发到自己的服务器 | 拿到 Cookie = 冒充登录 |
| **钓鱼** | 用 JS 盖一个和真页面一模一样的登录框 | 骗用户重新输入密码 |
| **蠕虫传播** | 自动转发带 payload 的链接/内容 | 指数级扩散 |
| **打后台** | 管理员查看留言时触发 | 拿到后台权限 |
| **内网横向** | 控制一个浏览器，借它访问内网系统 | 突破网络边界 |
**最核心的是第一条：盗 Cookie。** 因为一旦有了 Cookie，攻击者不需要密码就能以你的身份登录。
## 9.2 真实案例
### 2005 年 MySpace Samy 蠕虫
一个叫 Samy Kamkar 的人，在 MySpace 的个人主页里塞了一段 XSS 代码。
任何人访问他的主页，这段代码就会：
1. 把访问者加为他的好友
2. 把同样的代码复制到访问者自己的主页上
结果：**20 小时内感染了超过 100 万个用户主页**。
Samy 本人因此被判三年缓刑、社区服务，并被禁止使用电脑一段时间——他也成了"第一个因为 XSS 被判刑的人"。
### 2011 年新浪微博蠕虫
2011 年 6 月，微博上出现了一波 XSS 蠕虫：用户点开一条带 payload 的微博后，会自动转发、自动关注。
短时间内大量账号出现异常行为，微博紧急修复。
**这两次事件的共同点**：使用的技术就是最基础的 `<script>` 注入，没有任何高科技。
## 9.3 防守方的视角
| 环节 | XSS 怎么出现 |
| --- | --- |
| **代码审计** | 搜"输出点"——所有把用户输入写进 HTML 的地方 |
| **渗透测试** | XSS 是必测项，通常排在信息收集之后 |
| **SRC / 众测** | 最常见的漏洞类型之一，门槛低、数量多 |
| **应急响应** | 页面里突然出现陌生 `<script>`，第一反应就是 XSS |
| **WAF 运营** | 规则库里 XSS 特征占很大一部分 |
## 9.4 为什么它到今天还是那么常见
| 原因 | 说明 |
| --- | --- |
| **输出点太多** | 一个系统几百个页面，每个页面都要处理输出 |
| **上下文不同** | 输出到 HTML、属性、JS、CSS、URL，编码方式全不一样 |
| **框架不能全包** | 框架能处理大部分，但 `innerHTML`、`v-html`、`dangerouslySetInnerHTML` 一旦用了就前功尽弃 |
| **前端越来越复杂** | DOM XSS 在纯前端应用里激增 |
| **安全意识** | 很多开发者知道 SQL 注入，但对 XSS 只停留在"过滤 script" |
## 9.5 所以这份笔记的现实意义
| 场景 | 用得上什么 |
| --- | --- |
| 做安全测试 | 四步法 + payload 小抄 + 判定标准 |
| 写代码 | 知道输出必须转义，且要按上下文选择方式 |
| 做代码审计 | 知道去哪里找输出点 |
| 理解别人的攻击报告 | 看得懂 payload 在干什么 |

# 十、防御怎么写
## 10.1 核心：输出转义
```php
// 正确
$msg = htmlspecialchars($_GET['message'], ENT_QUOTES, 'UTF-8');
echo "<p class='notice'>who is {$msg},i don't care!</p>";
```
转义之后，`<` 变成 `&lt;`，浏览器只会把它当文字显示。
## 10.2 三层配合
| 层 | 做法 | 作用 |
| --- | --- | --- |
| **输出编码** | `htmlspecialchars()`、按上下文编码 | 核心，阻止代码执行 |
| **Cookie 保护** | `HttpOnly` | 让 JS 读不到 Cookie |
| **CSP** | `Content-Security-Policy` | 禁止内联脚本执行 |
## 10.3 为什么"输入过滤"不能当主力
因为黑名单永远会被绕过：
| 被拦的 | 换成 |
| --- | --- |
| `<script>` | `<img src=x onerror=>` |
| `<img>` | `<svg onload=>` |
| `<svg>` | `<body onload=>` |
| 小写 `script` | `<ScRiPt>` |
**输入过滤只能当辅助，输出转义才是根本。**

# 十一、下一步练什么
Pikachu 的 XSS 模块是递进的，建议按顺序打：
- [x] 反射型xss(get) —— 练"找入口 + 测回显"
- [ ] 反射型xss(post) —— 参数从 URL 换到表单
- [ ] 存储型xss —— 输入进数据库，危害最大
- [ ] DOM型xss —— 服务器不参与
- [ ] xss之盲打 —— 看不到回显怎么办
- [ ] xss之过滤 —— 黑名单绕过
- [ ] xss之htmlspecialchars —— 转义写错的情况
- [ ] xss之href输出 —— 输出位置不同，payload 不同
- [ ] xss之js输出 —— 输出到 JS 代码里
前面几关练"能不能注入"，后面几关练"被拦了怎么绕"。
