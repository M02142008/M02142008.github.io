# CTFHub Writeup - 默认口令

## 题目类型

WEB

## 题目描述

打开题目后，点开链接，界面显示一个亿邮邮件网关的登录界面

随便填写用户名、密码、验证码点击登录后

页面显示user is not exisits

## 解题过程

确认靶场为亿邮邮件网关后

根据公开的默认口令信息，在浏览器中搜索到亿邮邮件网关的默认凭证

在用户名和密码栏中输入

用户名：eyougw

密码：admin@(eyou)

把随机的验证码输入正确后，点击登录

页面就会显示出正确的Flag

## 笔记

这道题主要学习了：

1、默认口令漏洞（Default Credentials）的原理与危害

理解了在物联网设备、网关或 CMS 系统中，厂商通常会预置一套出厂默认的管理员账号密码（如本题“亿邮邮件网关”的 eyougw / admin@(eyou)）。

如果管理员部署后没有修改，攻击者就可以直接利用公开的默认凭据进入后台，这是渗透测试中最常见也最致命的基础漏洞之一。
 
2、用户名枚举漏洞的信息泄露利用

在踩坑阶段，我发现输入 admin 时，系统提示的是 user is not exists 而不是“密码错误”。

这暴露了系统“先校验用户名，再校验密码”的逻辑。

这是一个重要的渗透思路转变：遇到这种提示，不应该盲目去爆破密码，而是应该先去寻找正确的用户名。
 
3、信息收集（OSINT）在实战中的核心作用

对比上一关的“字典爆破”，这道题完美展示了信息收集的高效性。

通过识别目标系统的特征（“亿邮邮件网关”），直接去搜索引擎（百度/Google）搜索“默认口令/默认密码” + 设备名称，就能找到安全研究者整理好的公开凭据字典，一分钟就能突破系统，比纯靠算力爆破高效得多。
 
4、从“盲目爆破”到“精准打击”的思维升级

经历了弱口令、字典爆破、默认口令这三关，我彻底理顺了密码破解的优先级：

先手动试弱口令 -> 再搜公开默认凭据 -> 发现用户名枚举先纠正账号 -> 最后才考虑用 Burp Suite 或脚本去跑字典爆破。

这个排查顺位在未来的渗透测试中非常有指导意义。
