# 垂直越权 通关笔记

> 上一关是"看别人的数据"，这一关是"做更高权限的事"。
>
> 管理员页面加了 `level` 校验，**但有一个页面忘了加。**

---

## 一、环境与目标

| 项目 | 内容 |
| --- | --- |
| 靶场 | Pikachu |
| 关卡位置 | Over Permission → 垂直越权 |
| 登录页 | `http://pikachu/vul/overpermission/op2/op2_login.php` |
| 普通用户页 | `http://pikachu/vul/overpermission/op2/op2_user.php` |
| 管理员页 | `http://pikachu/vul/overpermission/op2/op2_admin.php` |
| 添加用户页 | `http://pikachu/vul/overpermission/op2/op2_admin_edit.php` |
| 提交方式 | POST 登录 |
| 测试账号 | `pikachu` / `000000`（普通用户，level=2） |
| 目标 | 用普通用户身份做管理员才能做的事 |

---

## 二、我的解题步骤

### 步骤 1：先用普通用户登录

用 `pikachu` / `000000` 登录。

**为什么是 pikachu 而不是 admin？**

因为 `users` 表里：

| 用户 | 密码 | level |
| --- | --- | --- |
| admin | 123456 | **1（管理员）** |
| pikachu | 000000 | **2（普通用户）** |
| test | abc123 | 3 |

登录代码：

```php
if($data['level']==1){ header("location:op2_admin.php"); }
if($data['level']==2){ header("location:op2_user.php"); }
```

**所以 pikachu 登录后进的是 `op2_user.php`。**

### 步骤 2：看普通用户的界面

```
欢迎来到后台管理中心,您只有查看权限!
```

一个表格，列出所有会员信息，**没有删除按钮，也没有添加用户**。

### 步骤 3：试直接访问管理员页面

```
op2_admin.php
```

**被重定向回了登录页。**

看源码：

```php
if(!check_op2_login($link) || $_SESSION['op2']['level']!=1){
    header("location:op2_login.php");
    exit();
}
```

**这个页面校验了 level，进不去。**

### 步骤 4：换一个管理员页面

管理员还有另一个页面——「添加用户」：

```
op2_admin_edit.php
```

**直接访问。**

**这次没有被踢走，页面正常打开了。**

### 步骤 5：看源码，找到问题

```php
// 判断是否登录，没有登录不能访问
//这里只是验证了登录状态，并没有验证级别，所以存在越权问题。
if(!check_op2_login($link)){
    header("location:op2_login.php");
    exit();
}
```

**作者的注释直接点破了：**

> 这里只是验证了登录状态，并没有验证级别，所以存在越权问题。

对比一下两个页面：

| 页面 | 校验 |
| --- | --- |
| `op2_admin.php` | `check_op2_login() && level==1` ✅ |
| `op2_admin_edit.php` | **只有 `check_op2_login()`** ❌ |

### 步骤 6：用普通用户添加管理员

在 `op2_admin_edit.php` 填入用户名密码，提交。

**`insert into member(...)` 执行成功——普通用户成功添加了一个新用户。**

我实测：

```
[op2 垂直越权] final URL = .../op2_admin_edit.php
[op2 垂直越权] 停留在编辑页: True
```

**pikachu（level=2）能直接访问并操作"添加用户"页面。**

## 三、原理分析

### 3.1 完整的漏洞链

```
1. pikachu 登录 → level=2 → 进 op2_user.php
2. 攻击者手动访问 op2_admin_edit.php
3. 服务端只检查"有没有登录" → 通过
4. 没有检查"level 是不是 1" → 越权
5. 普通用户执行了"添加用户"
```

### 3.2 为什么会有这种漏洞

因为权限校验**分散在每个文件里**，而不是统一做。

```php
// op2_admin.php 写了
if (!login || level != 1) redirect;

// op2_admin_edit.php 忘了写 level 判断
if (!login) redirect;
```

**只要有一个页面漏了，整条链路就通了。**

### 3.3 前端的"隐藏"不起作用

`op2_user.php` 的界面里没有"添加用户"的链接。

但**接口还在**——攻击者不需要点按钮，直接访问 URL 就行。

**"界面上看不到"≠"访问不到"。**

## 四、知识点与笔记

### 4.1 垂直越权的判断

| 步骤 | 操作 |
| --- | --- |
| 1 | 用低权限账号登录 |
| 2 | 抓包 / 看菜单，找出所有接口 |
| 3 | 逐个尝试直接访问高权限接口 |
| 4 | 看是否被拦 |

**关键：不要只看"界面上有什么"，要看"服务器上有哪些接口"。**

### 4.2 找接口的方法

| 方法 | 说明 |
| --- | --- |
| 看 JS 源码 | 前端路由、接口列表 |
| 看菜单 HTML | 被注释掉的链接 |
| 猜路径 | `/admin/`、`/manage/`、`edit`、`delete` |
| 看源码 | 如果有源码泄露 |
| 目录扫描 | dirsearch / 御剑 |

### 4.3 垂直越权常见的形态

| 形态 | 例子 |
| --- | --- |
| 直接访问管理页 | `/admin/user_list.php` |
| 调用管理接口 | `POST /api/user/delete` |
| 参数提权 | 请求里多传 `role=admin` |
| 隐藏功能 | 前端没按钮，接口还在 |

### 4.4 和水平越权的区别

| | 水平越权 | 垂直越权 |
| --- | --- | --- |
| 目标 | 同级别的别人 | **更高权限的功能** |
| 关键 | 数据归属没校验 | **功能权限没校验** |
| 危害 | 泄露 | **提权、控制整个系统** |

**垂直越权更危险——因为它能拿到管理员权限。**

---

## 五、和其他几关的区别

| 关卡 | 校验 | 问题 |
| --- | --- | --- |
| 水平越权（op1） | 有登录校验 | 身份来自参数 |
| **垂直越权（op2）** | **有的页面校验 level，有的没校验** | **校验不一致** |

## 六、防御怎么写

### 6.1 统一权限中间件（最重要）

```php
// 在每个页面开头统一调用
require_permission('admin');

function require_permission($role) {
    if (!isset($_SESSION['user'])) {
        header('Location: login.php');
        exit;
    }
    if ($_SESSION['user']['role'] !== $role) {
        http_response_code(403);
        exit('无权访问');
    }
}
```

**不要让每个页面自己写判断——一定会漏。**

### 6.2 用路由/中间件集中管理

```php
$routes = [
    '/user/list'   => ['auth' => true,  'role' => 'user'],
    '/admin/list'  => ['auth' => true,  'role' => 'admin'],
    '/admin/edit'  => ['auth' => true,  'role' => 'admin'],
    '/admin/delete'=> ['auth' => true,  'role' => 'admin'],
];
```

**每个路由都声明权限，统一检查。**

### 6.3 默认拒绝

```php
// 默认拒绝，只有明确允许的才放行
$allow = ['/login', '/register'];
if (!in_array($path, $allow)) {
    require_login();
}
```

### 6.4 前端隐藏 + 后端校验

**前端隐藏是"体验"，后端校验是"安全"。两个都要，但不能只靠前端。**

## 七、总结

| 要点 | 内容 |
| --- | --- |
| 这关教什么 | 权限校验不一致导致提权 |
| 关键点 | `op2_admin_edit.php` 忘了校验 level |
| 操作 | 普通用户直接访问 `op2_admin_edit.php` |
| 实测 | pikachu（level=2）能打开添加用户页 |
| 修复 | 统一权限中间件 + 默认拒绝 |

**一句话**：

> **权限校验只要漏了一个接口，整条防线就等于没设。**
