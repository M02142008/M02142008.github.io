# CTFHub Writeup - HG泄露 

## 题目类型

WEB

## 题目描述

打开题目，点开链接后，页面出现一个大标题：

信息泄露 - Mercurial

标题下面有一行文字：

Flag 在服务端旧版本的源代码中, 不太好使的情况下, 试着手工解决。

# 解题过程

## 入坑过程

首先用浏览器访问http://challenge-1590247e2b23a319.sandbox.ctfhub.com:10800/.hg/requires

浏览器会弹出下载require这个文件的界面，点击下载，同时也说明了漏洞确实存在

点击Win+R，搜索cmd，在黑框中输入：

wget -r -np -nH --cut-dirs=1 http://challenge-1590247e2b23a319.sandbox.ctfhub.com:10800/.hg/

回车后，界面显示'wget'不是内部或外部命令，也不是可运行的程序或批处理文件

我发现我的Windows没有装wget，所以开始尝试了新路径

## 新路径

在浏览器搜索框中输入：

http://challenge-c2740ff82eedba79.sandbox.ctfhub.com:10800/.hg/store/00manifest.i

http://challenge-c2740ff82eedba79.sandbox.ctfhub.com:10800/.hg/store/00changelog.i

下载出这两个核心文件并保存至桌面

访问https://gchq.github.io/CyberChef/

将刚刚下载的00manifest.i文件放入INPUT框内

OUTPUT框内就会显示解压出文件，里面会有一个文件名：

flag_90798518.txt

在浏览器的搜索栏中输入：

http://challenge-1590247e2b23a319.sandbox.ctfhub.com:10800/flag_90798518.txt

回车，页面就出现了正确的Flag

# 笔记

## 失败原因：

wget 是 Linux/Unix 系统下的一个命令行下载工具。

Windows 系统默认是不自带 wget 的，因此当你在 Windows 的 CMD 里敲下 wget 时，系统在自己的环境变量里找不到这个程序，所以直接报错说“不是内部或外部命令”。

## 这道题主要学习了：

1、Mercurial（HG）版本控制泄露的原理

理解了 Mercurial 和 Git、SVN 一样都是版本控制工具，如果配置不当，.hg 目录会直接暴露在 Web 服务器上。

核心利用路径是访问 /.hg/requires 确认漏洞存在，再下载 .hg/store/ 目录下的核心索引文件。
 
2、00manifest.i 与 00changelog.i 两个关键文件的作用

深入理解了 Mercurial 的数据存储机制：

• 00changelog.i 是提交日志索引，记录每次提交的信息（谁提交的、备注是什么）。

• 00manifest.i 是文件清单索引，记录仓库里所有文件的名称和哈希值。

解题的关键就是从 00manifest.i 里解压出那个藏有 Flag 的文件名。 

3、用 CyberChef 在线解压 Mercurial 二进制索引文件

掌握了 .i 文件的格式：前 64 字节是固定索引头，后面才是用 Zlib 压缩的真实数据。

学会了在 CyberChef 中配置 Drop bytes (Length=64) + Zlib Inflate 的配方，纯浏览器就能把二进制索引解压成人能看懂的文本。
 
4、HG 泄露的“非典型”利用思路

明白了这道题的巧妙之处：出题人把带 Flag 的文件添加到了仓库清单里（出现在 00manifest.i 中），但没有正式提交。

所以 .hg/store/data/ 目录下找不到该文件（会 404）。

但该文件被直接放在了网站根目录，只要从清单里拿到文件名，直接访问根目录就能下载到它。
