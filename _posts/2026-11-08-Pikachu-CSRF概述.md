## 二、CSRF 是什么
### 2.1 一句话
> **攻击者伪造一个请求，骗已经登录的用户去点。用户一点，攻击就完成了。**
因为受害者只需要"点一下"，所以 CSRF 也叫 **"one click" 攻击**。
### 2.2 页面里的场景
Pikachu 用了一个购物网站的例子：
**目标**：小黑想改掉大白在 `www.xx.com` 上的会员地址。
**白正常修改信息的流程**：
```
登录 → 修改会员信息 → 提交请求 → 修改成功
```
所以小黑要改大白的信息，理论上需要两样东西：
1. 大白的登录权限
2. 修改个人信息的请求
但大白不会把密码告诉小黑。
**小黑的做法**：
1. 自己去 `www.xx.com` 注册一个账号
2. 修改自己的信息，用抓包看请求长什么样
3. 发现请求是：
```
http://www.xxx.com/edit.php?email=xiaohei@88.com&Change=Change
```
4. 把这个链接伪造成别的形式，发给大白
5. 大白在**登录状态下**点了这个链接
6. 大白的信息被改成了小黑指定的内容
**整个攻击过程中，小黑一次都没有登录过大白的账号。**

## 三、成立需要三个条件
页面里写得很清楚，CSRF 要成功，需要"天时、地利、人和"：
| # | 条件 | 说明 |
| --- | --- | --- |
| 1 | **关键操作的请求容易被伪造** | 没有 token、没有验证码、没有二次确认 |
| 2 | **受害者已登录** | 浏览器会自动带上 Cookie |
| 3 | **受害者点了攻击者的链接** | 需要诱导，不能强行 |
三条缺一不可。
**其中第 1 条是网站的责任，第 2、3 条是攻击者要创造条件。**
### 3.1 判断一个网站有没有 CSRF
> **看它对"关键信息（密码、邮箱、地址、转账）的增删改操作，是否容易被伪造。**
不是所有请求都能做 CSRF：
| 操作类型 | 能否 CSRF |
| --- | --- |
| 查询（select） | 能伪造，但没什么危害 |
| **修改（update）** | **能，危害大** |
| **删除（delete）** | **能，危害大** |
| **新增（insert）** | **能，危害大** |

## 四、和 XSS 的区别（最重要的一段）
这两个概念最容易混。
### 4.1 页面里的对比
页面举了一个例子：
> 如果小黑事先在 xxx 网的首页发现了一个 XSS 漏洞，他可以：
>
> 1. 骗小白访问一个页面（页面里埋伏了盗 Cookie 的脚本）
> 2. 小白中招，Cookie 被发到小黑手里
> 3. 小黑用这个 Cookie 登录小白后台
> 4. 小黑自己动手改小白的信息
**对比一下：**
| | CSRF | XSS |
| --- | --- | --- |
| **攻击者拿到用户权限了吗** | **没有** | **拿到了** |
| **怎么完成攻击** | 借用户的浏览器发请求 | 在用户浏览器里执行代码 |
| **用户需要做什么** | 点一下链接 | 访问页面 |
| **攻击者能操作多久** | 只能做那一个请求 | 直到用户关掉页面 |
| **防御重点** | Token、验证码、二次确认 | 输出转义 |
### 4.2 一句话记住
> **CSRF 是"借"用户的权限完成攻击，攻击者并没有拿到用户的权限。**
>
> **XSS 是"盗"用户的权限，拿到之后自己动手。**
### 4.3 两者的关系
它们不是互斥的，可以配合：
- 有 XSS → 可以绕过 CSRF token（在同源下能读到 token）
- 有 CSRF → 可以在用户不知情的情况下执行操作
**但 XSS 的"级别"更高**——因为它直接拿到了身份。

## 五、和"越权"的区别
页面里提到，有人会把 CSRF 和越权混为一谈。
| | CSRF | 越权 |
| --- | --- | --- |
| **谁在操作** | **受害者自己**（浏览器自动发请求） | **攻击者自己** |
| **用什么身份** | 受害者的身份 | 攻击者的身份，去操作别人的数据 |
| **典型例子** | 骗你点链接，你的密码被改了 | 你把 URL 里的 `id=1` 改成 `id=2`，看到了别人的订单 |
**区别在于：CSRF 是你自己在操作（只是你不知道），越权是攻击者在操作。**

## 六、防御思路
页面里给了三条：
| 措施 | 说明 |
| --- | --- |
| **加 token** | 敏感操作要求带一个不可预测、不可被第三方读取的 token |
| **加验证码** | 增加"人"的参与 |
| **安全逻辑流程** | 比如改密码要先校验旧密码 |
补充几条实践中的：
| 措施 | 说明 |
| --- | --- |
| 检查 `Referer` / `Origin` | 判断请求是不是从本站发出的 |
| 关键操作二次确认 | 转账、改密码时弹确认框 |
| Cookie 设 `SameSite` | `Lax` 或 `Strict`，跨站请求不带 Cookie |
| 敏感操作只用 POST | GET 请求更容易被"链接"利用 |
---
## 七、总结
| 要点 | 内容 |
| --- | --- |
| CSRF 是什么 | 伪造请求，骗已登录用户点击 |
| 三个条件 | 请求可伪造、用户已登录、用户点了链接 |
| 和 XSS 的区别 | CSRF 借权限，XSS 盗权限 |
| 和越权的区别 | CSRF 是受害者自己操作，越权是攻击者操作 |
| 防御核心 | token + 验证码 + 二次确认 |
**一句话**：
> **CSRF 不偷你的密码，它只是"用你的手"按下了那个按钮。**
